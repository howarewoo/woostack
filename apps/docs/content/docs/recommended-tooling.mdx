These are my recommendations for working with coding agents, not requirements for
using Woostack. They cover the development environment, agent harness, and harness extensions.
For optional skills, see [External skills](/docs/external-skills).
For application technologies, see [Recommended tech stack](/docs/recommended-stack).

## Development environment and remote access

[Orca](https://orca.dev) is my recommendation for an IDE, or agent development environment
(ADE). It brings coding agents, worktrees, terminals, and code review into one application.

[Tailscale](https://tailscale.com/) provides remote access to your development machine over a
private network.

## Coding harness

[Pi](https://pi.dev/) is my recommended coding harness. Its core is deliberately small, with
extensions that add tools and change the terminal interface.

Enable Pi's built-in `grep`, `find`, and `ls` tools by default so agents can search and
explore the repository without writing shell commands for each lookup. Enable
[`codemode`](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/codemode.md)
to batch and chain tool calls in JavaScript, keeping intermediate results out of the
conversation. In `~/.pi/agent/settings.json`:

```json
{
  "defaultTools": ["+codemode", "+grep", "+find", "+ls"]
}
```

I use the following optional packages in my Pi setup. Woostack does not require them.
Extensions execute code, so review their source before installing them.

- [@howarewoo/pi-subagents](https://github.com/howarewoo/pi-subagents) delegates work to focused
  subagents with explicit tool grants. Subagent Hub lets you follow progress and steer or stop
  their work.
- [@howarewoo/pi-schedule](https://github.com/howarewoo/pi-schedule) schedules recurring cron and
  one-shot prompts that wake the session later. There is no daemon or OS crontab, so jobs fire
  only while that session is running. Pair it with `@howarewoo/pi-subagents` for periodic
  orchestrator check-ins.
- [@juicesharp/rpiv-ask-user-question](https://github.com/juicesharp/rpiv-mono/tree/main/packages/rpiv-ask-user-question)
  adds structured clarification dialogs with selectable options, custom answers, and previews.
- [@juicesharp/rpiv-todo](https://github.com/juicesharp/rpiv-mono/tree/main/packages/rpiv-todo)
  keeps a visible task list above the editor so you can follow the agent's progress.
- [@howarewoo/pi-btw](https://github.com/howarewoo/pi-btw) opens concurrent, read-only side
  conversations with saved thread history while the main agent continues working.
- [pi-web-access](https://github.com/nicobailon/pi-web-access) adds web search, page fetching,
  PDF text extraction, and video understanding.
- [pi-zentui](https://github.com/lmilojevicc/pi-zentui) customizes the terminal UI, including
  the editor, messages, progress display, and footer.

Subagents are not automatically isolated workspaces. Avoid concurrent edits to the same files;
separate sessions alone do not prevent editing conflicts.

### Compaction for long-running agents

Pi compacts automatically when the context exceeds the model's context window minus
`compaction.reserveTokens`, which defaults to `16384`. On a 1M-token model, that is about 984k
tokens. An always-on agent's chat can grow to hundreds of thousands of tokens well before then,
and every wake re-reads all of it.

Give each long-running agent its own `<home>/.pi/settings.json`, where `<home>` is the working
directory the agent runs in. Set `reserveTokens` per model with `compaction.modelOverrides`,
keyed by the exact `provider/modelId`. Replace the placeholder keys below with your model IDs.
These reserves make a 1M-token model and a 272k-token model both compact near 200k tokens:

```json
{
  "compaction": {
    "modelOverrides": {
      "provider/model-with-1m-window": { "reserveTokens": 800000 },
      "provider/model-with-272k-window": { "reserveTokens": 72000 }
    }
  }
}
```

Do not set one large top-level `compaction.reserveTokens` instead. Pi does not clamp the
threshold, so a reserve sized for a 1M-token model leaves a smaller-window model with a negative
budget, and that model compacts on every turn.

Pi reads settings when a session starts. A chat that is already running keeps its old threshold
until it restarts, or until you run `/reload` in an interactive session. If the chat is already
over the new threshold, it compacts on its next turn.

Pi reads project settings only from `.pi` in the working directory, after you trust the project.
Workers that run in a repository workspace do not inherit the agent home's settings. They use the
global `~/.pi/agent/settings.json`, plus the repository's `.pi/settings.json` if it has one.

Compaction replaces older messages with a summary. Keep durable state in files and tracked items,
such as issues and task lists, not in the conversation, so compaction does not lose anything the
agent needs.
