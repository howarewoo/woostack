title: Getting started
description: Install Woostack, review your project guidance, and plan a README update without changing application code.
---

Install Woostack in an existing Git repository, then ask your assistant to plan a Verification
section for its README. Along the way, you will review the guidance agents use in that repository.

## Before you start

You need an existing Git repository, Node.js and pnpm, and a [coding assistant](/docs/harnesses)
that can load skills. Open the same repository in your terminal and assistant.

Run the installation command in your terminal. Send the later requests to your assistant using
its [skill-loading mechanism](/docs/harnesses#native-skill-invocation). This tutorial needs network
access for installation, but no Woostack configuration or GitHub publication access.

## 1. Install the skills

From the repository root, run:

```bash
pnpx skills add howarewoo/woostack
```

Check your assistant's installed-skill view for `woostack-init` and `woostack-whiteboard`.
If either is missing, use [installation troubleshooting](/docs/guides/troubleshooting#your-assistant-cannot-find-a-woostack-skill).
Each skill works independently; this tutorial uses two of them for different tasks.

## 2. Review your project guidance

Send this request to your assistant:

```text
/woostack-init Help me adopt Woostack in this repository. Review README.md,
AGENTS.md, PRODUCT.md, DESIGN.md, and ARCHITECTURE.md. Reuse our settled decisions
and discuss any missing project intent, architecture, compatibility commitments,
and data-preservation rules with me before writing. Show the proposed changes
and apply only the agreed guidance edits. Do not change application source,
commit, or publish.
```

Init inspects the repository and consults with you before editing. Confirm who uses the project,
which interfaces must stay compatible, and which data must survive changes. An unreleased project
can still have users and important data.

Read the resulting guidance and report. Commands should match the repository's actual scripts,
and unresolved decisions should stay visible. An adequate file may remain unchanged.
The [document responsibilities reference](/docs/skills/woostack-init#document-responsibilities)
explains what belongs in each file.

## 3. Plan a README update

Ask for a documentation-only plan:

```text
/woostack-whiteboard Plan a Verification section for this repository's README.
Use its existing instructions and actual check commands. Reuse an existing
section if it already serves this purpose. Return the plan here; do not edit
files, file GitHub issues, or implement changes.
```

The result should name the sources inspected, propose the README content, and explain how to
check its accuracy. If the existing section is sufficient, the assistant should say so. Missing
check commands should be flagged rather than invented.

This step writes nothing. The plan stays in chat until you choose to [deliver the change](/docs/guides/ship-change).
You can also [refine the plan](/docs/guides/whiteboard) or browse the [task guides](/docs/guides).
