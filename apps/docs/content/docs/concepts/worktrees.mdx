A Git worktree is a separate checkout of the same repository. Each task can edit its own files
and branch while sharing the repository's Git objects.

<WorktreeIsolation />

## Ownership and writer access

Each physical workspace has one active writer. Concurrent writers need separate workspaces and
non-overlapping responsibilities. Sequential writers can reuse a workspace after host evidence
confirms the previous writer exited or relinquished access, and current Git facts confirm it is
safe to continue. Waiting alone does not prove release.

Orchestrate requires isolated task workers; it cannot replace a missing worker capability with
coordinator edits in the primary checkout. Standalone Execute can work inline in an approved
workspace with the same ownership safeguards.

## Base selection and dependencies

The selected base must contain the task's prerequisites. Git ancestry can prove commit-preserving
containment. A squash landing needs evidence of the landing and integrated content because the
old PR head may no longer be an ancestor.

An uncertain base or active writer blocks the affected task. Independent work can continue where
its own prerequisites and workspace ownership are established.

## Recovery and lifecycle

After an interruption, current worker state, branch diffs, and matching PRs establish the remaining
work. A lost response does not justify repeating a write or resetting another owner's checkout.
Publication also grants no permission to remove a workspace.

The [workspace reference](https://github.com/howarewoo/woostack/blob/main/shared/references/worktrees.md)
owns allocation and recovery safeguards. [Coordinate several tasks](/docs/guides/coordinate-work)
shows how to request delegated work.
