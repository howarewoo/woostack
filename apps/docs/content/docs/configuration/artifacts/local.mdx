Historical manifests, drafts, locks, plans, reports, and retired provider records remain user data.
Workflows do not allocate, resume, rewrite, migrate, or delete those records. No bundled reader or
setup helper is required. Existing records keep their contents and permissions.

Whiteboard implementation plans default to temporary Markdown files outside the target repository.
An explicit destination can retain a plan or review in a named document. Temporary files can be
cleared; they do not guarantee recovery or rewrite historical runs. Saving authorizes no
implementation. See [Plan a change](/docs/guides/whiteboard).

## Authority and recovery

Git and GitHub own source, branches, commits, pull requests, reviews, and merge state. A retained
record preserves decisions and evidence; it does not authorize publication, implementation,
assignment, ownership, acceptance, or merge.

Historical files and settings never select a GitHub destination. Requested publication resolves the
exact destination from the request and verified repository context. Project operations require an
explicit Project selection and the [capabilities that operation needs](/docs/configuration/artifacts/github).

To reuse historical planning evidence, supply the relevant content with one complete bounded task.
The responsible workflow validates current repository evidence before acting. A retained run ID alone
is insufficient; no automatic conversion, import, or publication is performed.

The retired `/woostack-execute --run <exact-run-id> [--recheck]` input is rejected. Select one
complete task as `/woostack-execute <bounded input>`; see
[Execute retired inputs](/docs/skills/woostack-execute#retired-inputs).

The canonical [retained-data contract](https://github.com/howarewoo/woostack/blob/main/shared/references/artifact-backends.md#retained-data-and-retirement)
owns these preservation rules.
