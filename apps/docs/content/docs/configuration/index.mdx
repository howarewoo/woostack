---
title: Workflow inputs
description: Where WooStack gets task scope, repository rules, host capabilities, and output locations.
---

WooStack skills require no repository-specific setup or configuration files. Each skill uses the
user's request, relevant repository instructions, and the host's available capabilities.

| Input | Source |
| --- | --- |
| Task scope and permission | The user's request and the selected workflow's authority boundaries. |
| Verification commands and required hooks | Repository instructions, source, manifests, and existing checks; explicitly requested preparation commands also apply. |
| Branch base | The approved task dependencies and verified Git/PR evidence. Ambiguous parent intent blocks affected work. |
| GitHub destination | The request and verified repository context, or an exact explicitly selected Project URL. |
| Model, effort, and authentication | The native host. Credentials stay in its secret store. |
| QA and visualization output | Fresh private host-temporary storage outside the checkout, or an explicitly requested output path. |

Applications and hosts own their configuration. Old WooStack settings and
historical records are user data: workflows do not interpret, validate, migrate, or delete them.
Their presence does not block unrelated work.
