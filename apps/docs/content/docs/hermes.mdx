Hermes acts as an external engineer: it coordinates decisions and reviews the evidence a coding
session returns. Install Woostack in [OMP](/docs/harnesses/omp), the harness that runs the agent
and its tools, not in Hermes. Hermes is not a supported Woostack host, and it must not edit source
code or replace repository evidence with its own conclusions.

<HermesActors />

## Before you start

You need:

- An approved task with defined scope and acceptance criteria, or a goal to plan.
- A read-only checkout for planning, and an isolated worktree for implementation.
- An interactive OMP profile with Woostack installed.
- A process or PTY interface that passes arguments safely and maintains a persistent handle.

The OMP session owns the selected phase, its focused verification, and the workspace. Hermes
verifies that each step remains within the approved task and reviews the returned evidence.

## 1. Start one persistent OMP session

Confirm installed CLI flags with `omp --help`, then start the session with each value as a
separate argument:

```text
omp --profile <profile> --cwd <checkout-or-worktree> <prompt>
```

Separate arguments prevent prompt text from becoming shell syntax. Do not add `-p` or `--print`:
those select non-interactive mode and exit after one response. If the interface cannot set a working
directory, put the exact worktree path in the prompt and require OMP to verify it before reading
or writing. Stop if profile, working directory, repository, branch, commit, or allowed paths do not
match the task.

## 2. Keep using the same process

Retain the process handle for the entire conversation. Send follow-ups, retries, and in-scope
corrections through that same process, attached to the same checkout. Run one process per active
conversation, never one per message. Never place task text, issue text, or user responses into
shell commands.

Planning in this session remains read-only. When implementation is approved, OMP or the repository
selects an isolated workspace for it.

## 3. Keep decisions inside the approved contract

Hermes may interpret the approved task, inspect OMP's diff and command output, review evidence,
accept a result that meets the contract, or request in-scope corrections. It may not expand scope,
edit source, run build or test commands, commit, push, open pull requests, or guess missing context.
It stops when evidence is missing, contradictory, or stale.

## 4. Escalate contract changes

Ask the responsible user about any new file path, changed acceptance criterion, unresolved decision,
or question outside approved scope. Keep OMP at its last verified point while waiting. A question
from the user does not itself approve a scope change.

## 5. Relay the user's response verbatim

An Ask is a question or approval choice that OMP needs the responsible user to decide. Relay only
that user's live response, verbatim and unmodified, through the same OMP process that asked. Do not
summarize, rewrite, or replay it. A decision the user already made remains settled; do not ask again
merely because a phase changed.

If the process restarts before a pending decision is settled, obtain a fresh answer and continue
through the new process.

## 6. Review evidence before accepting or redispatching

Inspect the exact checkout or worktree, branch, changed paths, complete diff, commands, observed
results, and blockers against the approved task. Re-read evidence after any correction. Do not
silently change profile, checkout, process, or contract. Git and GitHub remain authoritative for
code, branches, commits, pull requests, reviews, and merges.

## 7. Retained planning artifacts

Retained run records under `.woostack/tmp/runs/<run-id>/` remain readable historical data and are
never silently migrated or rewritten. A retained run ID is not an implementation request, and an
exact issue URL supplies context rather than implementation or publication authority. See
[OMP harness reference](/docs/harnesses/omp#planning-and-retained-records).

## 8. Clean up legacy launchers when safe

Cleanup is optional, owner-selected, and contingent on no active session or recovery path depending
on the files. Legacy installations may contain host-owned `launch-omp` or `bind-engineer-unit` files;
preserve needed evidence and remove only files the owner selects. Woostack does not install, invoke,
repair, or delete those launchers.
