**In development.** WooStack does not ship an autonomous-team runtime or installer. You can use
its existing skills with bots you already operate. The [R&D setup](/docs/agent-teams/setup)
describes a manual workflow, not a verified packaged integration.

## A team with defined responsibilities

Planning, coordination, implementation, and review are responsibilities, not a required number of
bots. One senior engineer can plan with Whiteboard and coordinate with Orchestrate when needed;
one junior engineer can implement bounded assignments with Execute. The same junior can handle
successive assignments without introducing another management layer.

Whiteboard uses the available context rather than requiring an interview. A delegated agent can
resolve decisions within the authority the user supplied and escalate consequential choices outside
it. The resulting plan carries enough context for another agent to continue without reconstructing
the planning conversation.

Independent review remains distinct from a planner's self-review. A required independent assessment
needs a suitable reviewer, but it is not an automatic third bot or mandatory stage for every change.

The proposed roles are:

- [Chief of staff](/docs/agent-teams/chief-of-staff): general coordination and platform operations.
- [CTO](/docs/agent-teams/cto): R&D priorities, assignments, and review routing.
- [Senior engineer](/docs/agent-teams/senior-engineer): assigned engineering work and junior review.
- [Junior engineer](/docs/agent-teams/junior-engineer): bounded implementation and evidence.

The chief of staff coordinates with department chiefs. The R&D CTO can assign work to the senior,
the junior, or an optional product designer. Other department chiefs are illustrative; only the
R&D setup is documented here. The senior is not a required dispatch route to the junior. When
authorized, the junior publishes a draft PR and sends the revision and evidence to the senior
for independent review and corrections. A human performs production and default-branch merges.

## Bounded handoffs and review

A handoff carries an objective, relevant context, allowed actions, expected output, and the
evidence needed to verify the result. Clear boundaries help the next agent continue the work
without treating background information as permission to expand it.

An agent's report distinguishes what it changed, what it checked, and what remains uncertain.
Review inspects the delivered artifact or exact revision and reports its findings and coverage.
That keeps implementation finished, review assigned, and review passed as separate states.
The host provides messaging, task state, and permission enforcement; Woostack supplies workflow
instructions, not another routing or approval engine.

## How it relates to agent skills

[Agent skills](/docs/agent-skills) provide task workflows inside a coding harness. Agent teams
concern ongoing organization and coordination: how responsibilities are divided, work is handed
over, and results are reviewed. Team setup and operating guidance live in the separate
Agent team documentation section.

[Whiteboard](/docs/guides/whiteboard) is the same planning entry point for people and delegated
agents. [Orchestrate](/docs/guides/coordinate-work) coordinates implementation under user approval
or explicit bounded delegation. A completed plan does not supply execution authority.
Neither skill requires the developing autonomous setup or a separate planning phase.

## Agent team documentation

Start with [setting up an R&D team](/docs/agent-teams/setup), then set up a [Shared wiki](/docs/agent-teams/shared-wiki) and adapt the role profiles and
[group chats](/docs/agent-teams/project-group-chats) to your work. The setup is a work in
progress, and does not guarantee autonomous operation.



## Current status

The team guides describe workflows using existing capabilities. Supported packaged environments,
installation, and end-to-end integration verification remain in development. The
[tech stack](/docs/recommended-stack) and [agent skills](/docs/agent-skills) can be used independently.

User decisions and permissions continue to bound the work. This overview grants no authority to
merge or deploy changes.
