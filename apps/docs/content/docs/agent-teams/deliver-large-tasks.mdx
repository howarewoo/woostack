---
title: Deliver a large task with an agent team
description: Keep one owner accountable for a multi-step request through verified delivery.
---

Use this work-in-progress practice with a host that supports the needed assignments and returns. It is guidance, not runtime or scheduler enforcement, a guarantee of future delivery, or a measured result. The user's scope, existing holds, permissions, and required approvals still apply.

## Accept and recover the work

1. Accept the request in a project room or a direct conversation with the relevant chief. Choose one root owner for the dominant outcome. That owner handles dependencies, delegation, integration, acceptance, and the final reply in the original conversation. An authorized chief can proceed without a chief-of-staff approval roundtrip.
2. Recover the original acceptance criteria, unfinished work, current holds, and applicable evidence. Do not silently cancel or restart work. Keep the goal, required proof, owner, return conversation, dependencies, next action, evidence, and blockers in the existing task checkpoint. The checkpoint does not require a new artifact or stage.
3. Give a brief dependency plan, then execute ordinary authorized steps without repeated go-aheads. Ask for a decision or approval only when the action needs one. Planning does not authorize implementation, publication, or deployment.

## Assign and integrate

Give each contributor a bounded deliverable, limits, exact inputs and revision, valid evidence, missing proof, dependency, and done condition. Default to one primary implementation per implementer. Run independent checks in parallel when their prerequisites are stable. If a shared contract is uncertain, verify a representative integrated slice before expanding dependent work.

Dispatch is not completion. Use the host's native assignment return and end the turn as the host requires. On return, inspect the actual artifacts and evidence, request concrete corrections, integrate the result, and continue authorized work. Keep required independent review. Select other reviewers for actual risks rather than using a blanket roster. Reuse equivalent proof while the relevant source, environment, and acceptance remain applicable. Refresh affected checks when those change or new interactions are integrated.

Before adding verification beyond required checks and reviews, identify the failure, consequence, affected boundary, and smallest adequate observation. Prefer existing checks over new machinery. Keep feedback in the existing task unless a separate delivery boundary is needed.

## Handle blockers and finish

Stop a diagnostic cycle that adds no relevant product or required safety evidence. Set aside the affected scope and continue safe independent work. Record the missing fact or capability, affected acceptance, next actor, and exact return condition. Wait for native completion or, for an external dependency, use one permitted bounded continuation where supported. Do not create unchanged recurring polling or claim a watcher exists. If no continuation is available, state how to resume manually.

Reply in the original conversation with artifact or PR links, acceptance proof, limits, and the precise human action still needed. Distinguish delivered, blocked, ready for a human, and live. A successful command, scaffold, or worker result does not establish root completion. All WooStack merges are human-only.

## Examples

These examples illustrate acceptance boundaries; they do not start work.

### Dependent pull request stack

Inventory every selected layer, exact head and base, and dependency. Inspect current reviews and checks, repair authorized conflicts or failures, and establish readiness bottom-up. Account for every layer and remaining gate in the final handoff. A human performs all merges.

### End-to-end web app

Retrieve current requirements, design decisions, repository instructions, and the requested WooStack stack guidance. Build and verify a representative integrated slice before expanding uncertain shared contracts. Complete, test, and review the agreed flows, then return usable artifacts and remaining gaps. Deploy only with authorization.
