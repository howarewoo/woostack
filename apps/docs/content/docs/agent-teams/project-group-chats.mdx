---
title: Group chats
description: Give a project room clear context, ownership, and bounded handoffs.
---

This work-in-progress practice uses a group as a shared coordination space. See OpenMausBot's
[collaboration documentation](https://docs.openmausbot.com/docs/features/chat-and-teams) for current
behavior. A mention alone is not proof that work was dispatched or completed.

1. Create one group chat per project. Include its accountable owner and department representatives
   needed for the work. The user posts the goal; representatives triage and delegate tasks, and
   coordinate across departments in the chat. Use it for project updates and management requests
   when useful. Add specialists only when their input is needed.
2. Share the project goal, repository, current state, relevant decisions, links to portable knowledge,
   and user-set permissions. Do not place credentials or unnecessary private information in the room.
3. Post a bootstrap message, replacing the placeholders:

```text
Project: [goal and repository]
Owner: [role or person]
Current state and decisions: [links and revision]
Allowed actions: [scope and limits]
Next outcome: [acceptance and required evidence]
Escalate: [decisions outside the owner's authority]
```

4. Assign each task to one owner using the host's actual delegation mechanism. Include the outcome,
   scope, workspace and revision, allowed actions, reviewer, checks, and return format.
5. Record decisions with sources. The owner checks the actual result and evidence, records open
   gaps, and reports completion only when the requested acceptance is met. Human authority governs
   production and default-branch merges.
