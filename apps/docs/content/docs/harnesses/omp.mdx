OMP is a supported coding harness that runs your agent and its tools. For native delegation,
Woostack uses agents already exposed by the active OMP session. Install Woostack in OMP, even when
an external engineer such as Hermes coordinates the work; Woostack does not install a second agent catalog.

## Native OMP agent routing

OMP's `task` tool selects an agent exposed by the active session. Its schema determines the dispatch
shape and whether effort is available; model routing and recovery belong to OMP. It has no per-call
model or working-directory field. Pass the selected workspace in a delegated task and have the worker
verify its checkout before writing. Without optional delegation, Execute can work inline; Orchestrate
reports the missing worker capability for affected delivery instead.

Orchestrate also supports [standalone workers](https://github.com/howarewoo/woostack/blob/main/shared/references/hosts/omp.md#standalone-workers)
launched with user or repository permission. Init provisions no project extensions and no agent
definitions. Older generated definitions are user-owned files and are never cleaned automatically.

## Native skill invocation

Invoke a Woostack skill in OMP with its documented command, for example `/skill:woostack-execute`.
Interactive mode registers one slash command per discovered skill when `skills.enableSkillCommands`
is enabled, and `/skill:<name> [args]` injects that skill's content
([skills](https://github.com/can1357/oh-my-pi/blob/main/docs/skills.md)). It is the same skill and
permissions as the `/woostack-*` form used elsewhere.

## Previously generated agent definitions

Older installations may contain `.omp/agents/woostack-{fast,standard,deep}.md`. Init and Doctor
leave these user-owned files alone; their absence is normal and is never a failure. Cleanup is
optional, manual, and user-initiated. Woostack never runs it automatically, and there is no migration
subsystem.

To remove only unchanged files generated by the retired provisioner:

1. Resolve the selected consumer repository to a canonical root and confirm each candidate was
   created by an older Woostack Init. An exact byte match is required but is not, by itself, proof
   of ownership. Obtain the historical provisioner from a separately verified `howarewoo/woostack`
   checkout at pre-retirement commit `cb3bbdc5789677bef2628390361ec9aa42e4827a`; do not assume that
   commit exists in the consumer repository. If the trusted source is unavailable, preserve the
   files for manual review.
2. Generate expected bytes in a separate temporary directory whose absolute path is canonicalized
   before invoking the historical provisioner. Never run it against the consumer repository.
3. Reject symlinked consumer `.omp` or `agents` directories. Compare each candidate with `cmp` and
   remove only a regular, non-symlink `.omp/agents/woostack-{fast,standard,deep}.md` file whose bytes
   match exactly and whose generated provenance is confirmed. Skip missing, modified, malformed,
   user-authored, or symlinked files, and keep every other agent and configuration entry.
4. Leave `.omp/agents/.gitignore` and unrelated ignore entries unchanged unless a user has
   separately confirmed, by provenance rather than filename, that a standalone `woostack-*.md` line
   was generated by Woostack. Any ambiguous, modified, symlinked, or user-owned entry stays in place
   for manual review.

Repeating the comparison and removal is idempotent and never follows or deletes a symlink target.
See OMP host notes for dispatch mechanics and
[retired session-naming](https://github.com/howarewoo/woostack/blob/main/shared/references/hosts/omp.md#retired-session-naming).

## Planning and retained records

Plan publishes issues only when the request asks for it, and explicit Project selection does not
infer Status mutations or extra authority. Credentials stay in the host secret store and never enter
repository configuration, prompts, logs, or generated output. The
[artifacts reference](/docs/configuration/artifacts) owns publication capability, retained-data
handling, and GitHub recovery.

Retained records contain plain Markdown files and a recovery manifest. They are planning evidence
only; Execute does not resume them or accept `--recheck`. See
[retained local records](/docs/configuration/artifacts/local).

## Recovery

Stop if the profile, working directory, worktree, branch, ancestry, or credentials no longer match
the verified task, or if process exit, verification, review, or submission results are incomplete
or conflicting. Preserve recoverable work and report the last safe point to resume. Never switch
profiles or worktrees silently, or claim results that a worker did not provide.
