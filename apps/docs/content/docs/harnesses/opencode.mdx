---
title: opencode
description: Delegation to discovered subagents through opencode's task tool.
---

In OpenCode V1, delegation uses the `task` tool when that permission is available. V2 uses a
different [permission schema](https://v2.opencode.ai/docs/permissions); check the active host schema
rather than applying V1 configuration unchanged. Select an agent exposed by the session whose
permissions suit the work; inline implementation remains available without an optional subagent.

opencode resolves its model and reasoning options from agent or session configuration. An
explicit one-run native override is passed only when the active `task` schema exposes its exact
field and the host permits it. Normal inheritance is not a limitation; unsupported optional
overrides are reported, and a required exact identity needs matching host evidence.

No per-worker working directory is documented. Pass the selected workspace in a delegated task
and have the worker verify it before writing. Provider recovery belongs to opencode.

Ask for a woostack skill by name: opencode's native `skill` tool loads the discovered skill, for
example `skill({ name: "woostack-execute" })` ([Agent Skills](https://opencode.ai/docs/skills/)).
Mentioning a subagent with `@` is a user chat shortcut, not a dispatch interface an agent can call.

The optional [opencode host notes](https://github.com/howarewoo/woostack/blob/main/shared/references/hosts/opencode.md)
record these mechanics against their sources.
