---
title: Publish a plan as issues
description: File a settled plan in GitHub and check that the issues and requested relationships exist.
---

Start with a settled plan, an exact GitHub repository or Project destination, and an assistant
with authorized issue-write access. Existing code needs repository access; a new product needs
no checkout. If material choices remain open, [refine the plan](/docs/guides/whiteboard) first.

<span id="1-describe-the-outcome" />

## 1. Select the plan and destination

Check that the plan includes bounded outcomes, non-goals, acceptance checks, and real prerequisites.
Group checkpoints into coherent issues. An implementation checkpoint does not need its own issue,
and necessary atomic changes should stay together.

Use the repository's actual owner and name in place of `OWNER/REPOSITORY` below. A Project is optional;
if you select one, supply its exact canonical URL.

<span id="2-review-and-optionally-publish" />

## 2. Request publication

Send this [request to your assistant](/docs/harnesses#native-skill-invocation):

```text
/woostack-whiteboard File the settled plan above as GitHub issues in OWNER/REPOSITORY.
Reuse existing issues that cover the outcomes. Include scope, non-goals,
acceptance checks, and real prerequisites, then read back the affected issues.
Do not start implementation.
```

This explicitly authorizes issue publication. A request to plan and publish in one message also
needs no separate publication approval. The assistant should return the actual issue URLs and
say which issues it created or reused.

If you require native sub-issue or dependency relationships, request them explicitly. They count
only after successful writes and independent read-back. Missing links do not erase verified issues,
but an explicitly required native graph remains incomplete until verified.

## 3. Check the result

Compare the returned issue content and prerequisites with the plan. If a write has an unknown
result, [inspect the target before retrying](/docs/guides/troubleshooting#an-issue-or-pull-request-write-has-an-unknown-result).
A success sentence alone is insufficient.

Choose implementation separately: [deliver one change](/docs/guides/ship-change) or
[coordinate several tasks](/docs/guides/coordinate-work). The
[Whiteboard publication reference](/docs/skills/woostack-whiteboard#saving-and-publishing)
defines the exact boundaries.
