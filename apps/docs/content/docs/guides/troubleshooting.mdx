---
title: Troubleshoot a blocked workflow
description: Check common blockers and resume without overwriting work or repeating uncertain writes.
---

Start with the symptom. Preserve existing files, branches, issues, and PRs while investigating.

## Your assistant cannot find a Woostack skill

Check the assistant's installed-skill view and confirm installation ran in the intended repository.
If needed, follow [Getting started](/docs/getting-started). Skill requests use the assistant's
[loading mechanism](/docs/harnesses#native-skill-invocation); they are not terminal commands.
Resume when the requested skill is discoverable. Its sibling skills need not be installed.

## Prototype cannot preview or save its output

Check that the host provides writable artifact storage outside the target project and a permitted
browser/runtime for the isolated preview. Do not put the prototype in an ignored project directory
or run project setup as a workaround. Missing storage blocks artifact creation; missing preview
capabilities leave the affected visual and interaction checks unverified, not passed.

Continue useful draft work within the available capabilities and report what is missing. Optional
external design skills are not prerequisites and need no installation to unblock the normal workflow.
See [Prototype isolation](/docs/skills/woostack-prototype#isolate-the-work).

## GitHub access fails

Check the host's GitHub capability and access to the exact target. Keep credentials in the host
secret store. Re-read the target through the authorized integration before retrying publication;
a local check cannot prove remote access. Missing access blocks that operation, not unrelated
local work. See [GitHub publication](/docs/configuration/artifacts/github).

<span id="orchestrate-is-blocked-by-missing-sub-issues" />

## Issues exist but native links are missing

Read the issue URLs, content, and declared prerequisites. A complete readable tracker can supply
executable scope without native sub-issues. Resume coordination when the selected tasks and their
real prerequisites are available. Missing required source content still blocks the dependent task.

Native relationships count only after write and read-back succeed. If the request explicitly
requires a native graph, report it incomplete until verified. See [issue publication](/docs/guides/plan-work)
and [Orchestrate](/docs/skills/woostack-orchestrate).

## An issue or pull-request write has an unknown result

Search the exact repository for the issue identity or matching branch PR and read its current state.
A timeout or lost response is not proof of failure. Preserve any confirmed write and resume only
the unverified step. Follow the [delivery procedure](https://github.com/howarewoo/woostack/blob/main/shared/references/delivery.md).

## A prior worker may still be active

Check native worker state and the worktree's branch, index, and diff. Start another writer in that
workspace only after evidence shows the previous writer exited or relinquished access. Waiting
alone is insufficient. Independent work can continue in a separate owned workspace.

## A check failed or did not run

Read the command, output, and affected path. Correct in-scope failures and rerun affected checks.
If a required check cannot run, name the unverified criterion and what must change before resuming.
A worker summary cannot supply missing evidence. Use [bounded diagnosis](https://github.com/howarewoo/woostack/blob/main/shared/references/tdd.md#slow-checks-bounded-diagnosis-no-waiver)
instead of repeated unchanged attempts. [Debug](/docs/skills/woostack-debug) can investigate without editing.

## A diagnosis claims the directory is not a Git repository

Run this read-only probe, replacing the placeholder with the target path:

```bash
git -C <target-directory> rev-parse --show-toplevel
```

A listing without `.git` is inconclusive: Git may use a hidden directory, a worktree file, or parent
metadata. If discovery succeeds, inspect HEAD and relevant changes before citing committed source.
If Git or the target is inaccessible, report repository status as unknown.

## A command has been retired

`woostack-build`, `woostack-fix`, `woostack-change`, `woostack-status`, `woostack-tdd`,
`woostack-prepare`, `woostack-plan`, `woostack-ideate`, `woostack-harden`, and `woostack-design` have no aliases.
Update old bot instructions using the [current command index](/docs/skills/using-woostack#command-routing).
Whiteboard handles planning and review; Execute handles bounded implementation. Old run records
remain historical data and must not be migrated or deleted automatically.

For former Design use, choose [Prototype](/docs/skills/woostack-prototype) for isolated interactive
mockups or Execute for authorized production UI changes. In an older installation, inspect the
host's installed-skill list, preserve any customizations, and remove only the retired
`woostack-design` through its supported management mechanism. Do not remove `woostack-design-system`.
Install Prototype in the intended host/scope using the supported installer, for example:

```bash
pnpx skills add howarewoo/woostack --skill woostack-prototype
```

Confirm that Prototype is discoverable and the retired Design copy is no longer active. Installing
the new name does not establish that the old local copy was removed; no automatic cleanup or alias
is provided.

## Still blocked

Share the intended outcome, exact repository, skill and host, observed error, last verified
commit or PR, checks and results, and the step that remains unverified. Remove secrets, private
source, and personal paths. Do not reset, clean, delete, or duplicate work to bypass the blocker.
