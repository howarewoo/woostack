title: Configuration
description: Non-secret repository policy, local run authority, and optional safe Linear/Plane defaults.
---

woostack resolves non-secret repository policy by layering tracked base configuration with an
optional primary-checkout local override:

1. **Tracked base:** `.woostack/config.json` contains committed repository policy.
2. **Optional local override:** `.woostack/config.local.json` contains gitignored (`*.local.*`)
   overrides in the primary checkout. Linked worktrees automatically inherit the primary checkout's
   local configuration.

[woostack-init](/docs/skills/woostack-init) creates the base file without requiring a provider connection
and automatically attempts safe read-only Linear default discovery when the host exposes the official
authenticated MCP. Missing or incomplete Linear setup never blocks local initialization. Configuration
never contains credentials or grants permission to perform repository work.

Local run manifests in `.woostack/tmp/runs/<run-id>/` own current Build/Fix product scope and execution
plans. Git and GitHub own code, branches, commits, pull requests, reviews, and merge truth. Init's
discovery calls authorize no later access. `artifacts.provider: "local"` is the default: workflows
operate with default zero-provider local authority. When `artifacts.provider: "linear"` or `artifacts.provider: "plane"`, a validated
`artifacts.linear` or `artifacts.plane` object supplies defaults for optional provider mirroring. Policy cannot authorize a write.

Tracked legacy records remain local unless the user explicitly invokes the guarded
`/woostack-init --migrate-legacy` route. The
[woostack-init migration contract](/docs/skills/woostack-init#optional-guarded-legacy-migration)
owns its import, preservation, recovery, and deletion boundaries.

The init template ships four top-level keys: `artifacts`, `models`, `review`, and `status`, with
`artifacts.provider` set to `"local"`. Other supported settings use built-in defaults.
[woostack-doctor](/docs/skills/woostack-doctor) checks static policy; Build and post-proof Fix manage
local runs, while provider mirror connectivity is checked when `artifacts.provider` is `"linear"` or `"plane"`.


### Layered merge rules

- **Recursive overlay:** objects merge recursively. A local scalar, array, or null replaces the base value.
- **Absent configuration:** when both `.woostack/config.json` and `.woostack/config.local.json` are absent,
  each consumer preserves its existing built-in defaults.
- **Fail-closed safety:** an empty, malformed, non-object, unreadable, symlink, non-regular, orphan local,
  or credential-like configuration file fails closed immediately with the offending path.
- **Non-secret only:** base and local configuration files contain non-secret policy only. Provider
  credentials stay strictly in the host's secret store.
- **Doctor runtime distinction:** [woostack-doctor](/docs/skills/woostack-doctor) validates effective
  configuration at runtime; template presence checks and auto-repairs apply strictly to the tracked
  base `.woostack/config.json`.

### Layered override example

Given a tracked base `.woostack/config.json`:

```json
{
  "artifacts": {
    "provider": "local",
    "linear": {
      "repository": "https://github.com/acme/widgets",
      "workspace": "acme",
      "team": "ENG"
    }
  }
}
```

And a primary-checkout `.woostack/config.local.json`:

```json
{
  "artifacts": {
    "linear": {
      "team": "LOCAL-ENG"
    }
  }
}
```

The canonical resolver merges them into effective policy with `"team": "LOCAL-ENG"` while
preserving `"repository"` and `"workspace"`.
**OMP exception:** woostack uses
[host-owned role routing](https://github.com/howarewoo/woostack/blob/main/skills/using-woostack/references/hosts/omp.md)
through three init-managed project workers. OMP ignores `.woostack/config.json` model settings and
owns its isolated profile, role configuration, concrete model identity, provider authentication,
and recovery.

There are eight top-level settings:

| Setting | Read by | Tunes |
| --- | --- | --- |
| `artifacts` | Automatic read-only setup in [woostack-init](/docs/skills/woostack-init), optional Linear/Plane mirroring in Build, Fix, and Plan (`artifacts.provider: "linear"` or `"plane"`), and selected standalone artifacts | `provider` selects `"local"` (default), `"linear"`, or `"plane"`; `linear` and `plane` store validated non-secret repository, workspace, team/baseUrl, `projectLabels`, and native-name defaults; never authorizes a provider write or content approval |
| `review` | [woostack-review](/docs/skills/woostack-review) | the PR review engine: angles, noise, validation |
| `models` | [woostack-review](/docs/skills/woostack-review), [woostack-audit](/docs/skills/woostack-audit), and host subagent drivers | shared model selection and tier parameters for hosts that consume repository model configuration; ignored by OMP |
| `audit` | [woostack-audit](/docs/skills/woostack-audit) | standing-code audit angles, filtering, chunking, and output |
| `review_sweep` | [woostack-sweep](/docs/skills/woostack-sweep) | how many review rounds a stack sweep runs |
| `commit` | [woostack-commit](/docs/skills/woostack-commit) | a pre-commit hook command |
| `status` | [woostack-status](/docs/skills/woostack-status) | when active repository rows are stale |
| `base_branch` | [woostack-init](/docs/skills/woostack-init) | the trunk branch for PRs and worktrees |
## A complete repository-policy example

The example keeps the shipped provider-free default. Authenticated read-only discovery through the official
Linear MCP may add validated non-secret Linear defaults; Plane `baseUrl`, workspace, repository, labels,
and native-name defaults are manually configured non-secret policy. Provider defaults do not authorize access;
only explicit workflow selection plus `artifacts.provider: "linear"` or `artifacts.provider: "plane"` admits mirroring.
JSON has no comments, so each key is explained below.

```json
{
  "artifacts": {
    "provider": "local"
  },
  "review": {
    "severity_floor": "high",
    "nits": true,
    "angles": {
      "force": ["tests"],
      "skip": ["seo"]
    },
    "ignore": ["**/*.generated.ts", "pnpm-lock.yaml"],
    "project_rules": ["docs/engineering/rules.md"],
    "authors_skip": ["dependabot[bot]", "renovate[bot]"],
    "force_tier": "",
    "chunking": { "max_loc": 4000 },
    "defer_markers": true,
    "metrics": false
  },
  "models": {
    "fast": { "model": "google/gemini-3-5-flash", "effort": "low" },
    "standard": { "model": "openai/gpt-5.5", "effort": "medium" },
    "deep": { "model": "anthropic/claude-opus-4-8", "effort": "xhigh" }
  },
  "audit": {
    "severity_floor": "high",
    "angles": {
      "force": [],
      "skip": ["deps"]
    },
    "ignore": ["**/*.generated.ts"],
    "chunking": { "max_loc": 4000 },
    "report_dir": ".woostack/audits"
  },
  "review_sweep": { "max_rounds": 3 },
  "commit": { "pre_commit": "pnpm format && pnpm test" },
  "status": { "staleDays": 14 },
  "base_branch": "main"
}
```

## Artifacts, Linear, and Plane configuration

Optional provider mirroring connects through the host's authenticated official Linear or Plane MCP.
Linear connects to the official endpoint:

```text
https://mcp.linear.app/mcp
```

Plane connects to the official Plane MCP for Plane Cloud (`https://api.plane.so` / `https://app.plane.so`)
or a self-hosted instance configured with `baseUrl` and `workspace`.

Authentication stays in the host's MCP/OAuth secret store. No API key, credential, authorization
value, or credential-file path belongs in repository configuration, prompts, logs, generated files,
or artifacts. Workflows prove capability without reading the secret.

`artifacts.provider` (string, default `"local"`) gates all development-artifact and mirror calls.
The automatic authenticated read-only Init discovery described above is the sole setup exception.
When `"local"` or omitted, development workflows operate with default zero-provider local authority.
Supplying `--project` when `artifacts.provider` is not configured for mirroring fails closed
immediately with an error stating that `--project` requires configured provider mirroring.
Legacy `linear.saveArtifacts` is rejected with explicit migration guidance to `artifacts.provider`
and `artifacts.linear`.

Woostack applies one provider-neutral artifact contract, then loads only the selected provider
profile. The shared layer owns local authority, persistence, mutation ordering, failure handling, and
independent read-back. Linear and Plane profiles independently define configuration, scope,
capabilities, identities, labels, graph operations, and lifecycle support. A future provider is added
as another profile with deterministic contract coverage rather than another branch in the shared
authority model.

When `artifacts.provider: "linear"` is configured, the `artifacts.linear` object provides
repository/workspace/team, `projectLabels`, and native-name defaults. Build uses them when creating
its canonical project if no exact project was supplied. After root-cause proof, Fix resolves a supplied
canonical project or uses the same defaults to create one. Default init may populate missing fields from
authenticated read-only discovery and independently validates any local config write. That narrow setup
neither selects artifact persistence nor authorizes later provider access.

When `artifacts.provider: "plane"` is configured, the `artifacts.plane` object provides
`baseUrl`, `workspace`, canonical `repository`, `projectLabels`, and native-name defaults.
Build uses them to resolve or create the canonical repository project named `[Repo] owner/name` and create its top-level specification work item `[Build] <goal>`.
`artifacts.linear.projectLabels` (array of strings, required when `artifacts.provider: "linear"`, empty array allowed) and
`artifacts.plane.projectLabels` (array of strings, required non-empty array when `artifacts.provider: "plane"`) configure
workspace project labels to attach to every admitted or created project. Project admission completely paginates workspace project labels through the
official provider MCP, flattens every page, requires a null terminal cursor, resolves each label by exact native ID or exact
case-sensitive name, unions configured labels with existing labels (preserving unrelated labels), writes once, and independently
reads the complete label set back. If the official Plane MCP lacks project-label operations, Plane persistence fails closed at the provider boundary.
Before configured or explicitly selected provider access, the workflow verifies the canonical
repository association and workspace/team, then preflights every complete project, issue, relation,
comment/decision, mutation, pagination, and independent read-back capability needed at that
boundary.

Build and post-proof Fix manage local runs in `.woostack/tmp/runs/<run-id>/`. Both write plain
`project-spec.md` and `execution-plan.md` artifacts, and perform one bounded mirror synchronization cycle
when `artifacts.provider: "linear"` or `artifacts.provider: "plane"`.
Mirror failure is recorded in the manifest and is nonblocking for
local authority. All run artifacts are retained upon completion and explicit abandonment to preserve
the audit trail. A nonterminal run can resume exactly with
`/woostack-execute --run <exact-run-id> [--recheck]`. Before root-cause proof, Fix makes no provider
call. `woostack-change` ignores the `artifacts` object.

`artifacts.linear.projectStatuses.started` names the native project status used when Execute in provider mode
observes any direct issue matching the configured `artifacts.linear.issueStates.executing` or
`artifacts.linear.issueStates.inReview` mapping by stable native identity and category. It resolves to exactly
one status in the selected workspace/team and must have native category `started`. Execute updates only
the exact project's status, with a stable mutation identity and independent read-back; an exact match
is an idempotent no-op. If all direct issues are `Backlog`/`Todo`, synchronization waits until the
selected issue transitions to the resolved executing mapping and reads back before repository
mutation. Local run mode (`--run`) bypasses provider status synchronization.

`artifacts.linear.issueStates.executing` and `artifacts.linear.issueStates.inReview` name the native issue states used by
Execute for active and delivered lifecycle evidence in provider modes. Execute resolves both mappings
to exactly one native state in the selected workspace/team and compares stable ID, name, and category
rather than using a literal native status name as authority. The resolved `inReview` mapping must have
native category `started`. The full independently read delivery checkpoint, not state alone, proves a
delivered issue and gates teardown, resume, and sibling progression.

Default-only teams without a custom review status should set `artifacts.linear.issueStates.inReview` to
`In Progress`, which may be the same native state as `executing`. Existing teams may keep a valid
custom `In Review` mapping. Manual migration changes only the mapped value in the repository
configuration; workflows never create, rename, or substitute Linear statuses, and no automatic
provider or configuration migration occurs.

`artifacts.linear.projectStatuses.canceled` names the native status used to close an existing project-backed
standalone Plan workflow after explicit abandonment. It must resolve to exactly one native status with
category `canceled`; the workflow pre-reads the exact project, updates only its status with a stable
mutation identity, and independently reads the transition back. The workflow never creates a project
solely to cancel it. Local Build and project-backed Fix record `status: "abandoned"` in the run
manifest and retain run artifacts without mutating a mirrored Linear project. Source issues, handoff,
replanning, and blockers are not abandonment and leave projects open.
### Optional Bootstrap and Commit provider writers

Optional provider writers require explicit opt-in and operate strictly through official host-exposed MCPs:

- **`woostack-bootstrap` (design persistence):** When the caller explicitly requests provider persistence or supplies an exact project URL/UUID, Bootstrap verifies the configured provider (`artifacts.provider: "linear"` or `"plane"`), waits for explicit design approval, resolves or creates one canonical feature project (applying required `artifacts.plane.projectLabels` for Plane), appends `designApproved`, and reads back the complete project state. Capability or sync failure blocks only the optional persistence operation without breaking local authority or releasing the filesystem barrier.
- **`woostack-commit` (PR attribution and delivery notes):** When invoked with `--issue <id>`, Commit verifies the exact canonical issue/work-item reference against the repository boundary via the configured official MCP (`linear` or `plane`), appends `Resolves <id>` to the PR body, and optionally writes a concise delivery note with independent read-back. PR and merge authority remains human-only on GitHub; provider sync failure is nonblocking for commit/PR delivery.

The canonical
[Local run artifact and provider mirror contract](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/artifact-backends.md)
owns identity, untrusted-data handling, hierarchy, failure boundaries, and synchronization receipts.

Hermes is an external engineer, not a supported coding harness or installed woostack runtime. If
used, Hermes drives one persistent OMP process for in-contract decisions and evidence review;
woostack remains installed only in OMP or another coding harness. When Hermes participates in an
active conversation, the responsible user's live response must be relayed verbatim; cross-session
resume against retained unchanged local run artifacts does not require the original process to stay
alive. The [Hermes guide](/docs/hermes) owns safe argument passing, escalation, verbatim relay, and
fail-closed restart/replay behavior.
## Review engine

All review keys nest under `review`. [woostack-review](/docs/skills/woostack-review) validates the
types when it runs; an unknown key inside `review` is a hard error.

### Finding severity and nits

A finding at or above the severity floor is a normal (blocking-eligible) finding. A finding below
the floor is surfaced as a non-blocking nit, or dropped entirely when nits are off. A below-floor
finding explicitly marked blocking always surfaces regardless of the floor.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `review.severity_floor` | string | `"high"` | Threshold: `low`, `medium`, or `high` (case-insensitive). |
| `review.nits` | boolean | `true` | `true` posts below-floor findings as `Nit:` comments; `false` drops them. |

### Angle selection

Angles are auto-detected from the diff and prefetched review context. Force an angle to run it regardless of detection; skip one
to keep it off. `force` wins when an angle appears in both. The `bugs`, `security`, and `simplify`
angles can never be skipped. They are silently kept even if listed.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `review.angles.force` | array of string | `[]` | Angles always enabled. |
| `review.angles.skip` | array of string | `[]` | Angles never enabled (except `bugs` / `security` / `simplify`). |

See the [review angle reference](/docs/concepts/review-angles) for all 22 angles, including what
each one audits, when it runs automatically, and its model tier.

### Filtering the diff

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `review.ignore` | array of string | `[]` | fnmatch globs; matching files are excluded from angle detection and from the diff body before analysis. |
| `review.project_rules` | array of string | `[]` | fnmatch globs of extra rule files appended to the auto-discovered `rules.md`; triggers the `conventions` angle. |

### Skipping PRs automatically

Some PRs should short-circuit the whole review with a skip comment. By default, three bot authors
are skipped (`dependabot[bot]`, `renovate[bot]`, and `github-actions[bot]`), and PR titles
matching the release-rollup pattern `^(staging\|release\|chore\(release\))` are skipped. Set either
to opt out: an empty array for `authors_skip`, or an empty string for the pattern.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `review.authors_skip` | array of string | three bots (above) | PR author logins that short-circuit the review. `[]` opts out. |
| `review.release_rollup_pattern` | string | release regex (above) | Python regex matched against the PR title. `""` opts out. |

### Model selection

Each review subagent runs at a tier (`fast`, `standard`, or `deep`). On hosts that consume
repository model configuration, the top-level `models` namespace maps that tier to a concrete
model and optional effort. The namespace sits at the root, not under `review`, so review, audit,
and local subagent drivers can share it.

omp is the host-owned exception. It ignores the entire `models` namespace and maps the effective
tier to its fixed init-managed role worker instead. Changing a flat or provider-specific model leaf
never changes an omp dispatch.

| Host | Repository model config | Flat fallback | Dispatch behavior |
| --- | --- | --- | --- |
| Claude Code | `models.anthropic.fast`, `.standard`, or `.deep` | matching flat leaf | Passes the resolved Anthropic model and effort to each Task call. The single-session CI action can pass the model, but not effort. |
| Codex | `models.openai.fast`, `.standard`, or `.deep` | matching flat leaf | Passes the resolved OpenAI model and reasoning effort when the host supports per-call overrides. A single-model session resolves once for the whole run. |
| Gemini | `models.google.fast`, `.standard`, or `.deep` | matching flat leaf | Uses the Google model for the resolved tier. |
| OpenRouter | `models.openrouter.fast`, `.standard`, or `.deep` | matching flat leaf | Uses the OpenRouter model and reasoning effort for the resolved tier. |
| omp (Oh My Pi) | ignored | ignored | Selects the fixed role-backed worker; omp owns its model and fallback. |

For hosts that consume this namespace, a provider-specific leaf takes precedence over the
matching flat leaf. The same config file can therefore supply provider-neutral defaults and
provider-specific overrides:

```json
{
  "models": {
    "fast": { "model": "google/gemini-3-5-flash", "effort": "low" },
    "standard": { "model": "openai-codex/gpt-5.6-sol", "effort": "medium" },
    "deep": { "model": "anthropic/claude-opus-4-8", "effort": "xhigh" },
    "anthropic": {
      "fast": { "model": "claude-opus-4-8", "effort": "low" },
      "standard": { "model": "claude-opus-4-8", "effort": "medium" },
      "deep": { "model": "claude-opus-4-8", "effort": "xhigh" }
    },
    "openai": {
      "fast": { "model": "gpt-5.5", "effort": "low" },
      "standard": { "model": "gpt-5.5", "effort": "medium" },
      "deep": { "model": "gpt-5.5", "effort": "high" }
    }
  }
}
```

In this example, Claude Code selects the Anthropic branch and Codex selects the OpenAI branch.
Another repository-model host can use the flat leaves. omp ignores every entry in the block.
How each non-omp host consumes the schema, including spawn primitives, per-call routing knobs,
and fallback, lives in its canonical host reference under
`skills/using-woostack/references/hosts/`.

Each tier leaf supports all three shared forms:

- a model-slug string;
- an object `{ "model": "<slug>", "effort": "<level>" }`; or
- a non-empty ordered array of either form, used as a fallback preference list.

Supported effort levels are `minimal`, `low`, `medium`, `high`, and `xhigh`.
`review.force_tier` pins every review subagent to one tier, like running the review with `--fast`
or `--deep`.

In an array leaf, entry 0 is the primary and has the exact semantics of the bare value. Entries
1..n declare a static preference order; runtime enactment remains host-specific. A review host
with an explicit per-call model override can redispatch a rate-limited worker along later entries;
other consumers follow their host reference. omp does not read or enact the array. An empty array
is a hard config error.

```json
{
  "models": {
    "deep": [
      { "model": "openai-codex/gpt-5.6-sol", "effort": "xhigh" },
      { "model": "openai-codex/gpt-5.6-sol", "effort": "high" },
      "google/gemini-3-5-flash"
    ]
  }
}
```

The [complete example](#a-complete-example) uses flat leaves to assign non-omp hosts a model for
each tier.

**Clean break:** `models` moved out of `review`. A `review.models` block is a hard config error.
Move it to the top level. `woostack-doctor` warns on a lingering `review.models`.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `models.fast`, `models.standard`, `models.deep` | string, `{model, effort}`, or array of those (fallback list) | provider table | Provider-agnostic model for the three shared tiers on repository-model hosts. |
| `models.anthropic.*`, `models.openai.*`, `models.google.*`, `models.openrouter.*` | string, `{model, effort}`, or array of those (fallback list) | provider table | Per-provider override, with one `fast`, `standard`, or `deep` leaf. |
| `review.force_tier` | string | absent (= standard) | Pin every subagent to `fast` or `deep`. Empty string = absent. |

The default model per provider and tier:

| Provider | `fast` | `standard` | `deep` |
| --- | --- | --- | --- |
| anthropic | `claude-opus-4-8` (effort `low`) | `claude-opus-4-8` (effort `medium`) | `claude-opus-4-8` (effort `xhigh`) |
| openai | `gpt-5.5` | `gpt-5.5` | `gpt-5.5` |
| google | `gemini-3-5-flash` | `gemini-3-5-flash` | `gemini-3-5-flash` |
| openrouter | `openrouter/deepseek/deepseek-v4-flash` | `openrouter/deepseek/deepseek-v4-pro` | `openrouter/deepseek/deepseek-v4-pro` |

Anthropic routes every tier to `claude-opus-4-8`, so the tier is carried by reasoning `effort`
(`low`/`medium`/`xhigh`) rather than by the model. Effort applies on per-call hosts (Claude Code);
the CI single-session `claude-code-action` step passes only the model.

On repository-model hosts, the tier resolves by precedence, highest to lowest: an inline
`--fast` / `--deep` comment on the PR → the action's `force_tier` input →
`review.force_tier` → the action's `model` input → the matching provider-specific leaf → the
matching flat leaf → the provider table default. On omp, only the effective-tier decisions apply;
the fixed worker map replaces every model-resolution step.

### Chunking, adjudication, and metrics

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `review.chunking.max_loc` | integer ≥ 0 | `4000` | Changed-line threshold; a larger diff is split into chunks and each angle fans out across them. `0` disables chunking. |
| `review.defer_markers` | boolean | `true` | `true` honors inline `woostack-defer(<ref>)` markers, demoting a matching finding to a non-blocking nit. `security` findings are never deferred. |
| `review.metrics` | boolean | `false` | `true` writes a per-angle signal/noise breakdown, folds a rolling non-authoritative local `.woostack/metrics.json`, and prints advisory `review.angles.skip` suggestions when an optional angle has at least 20 local runs with zero blockers and either zero kept findings or only nit findings. |
| `review.fix_commands` | array of string | `[]` | Reserved for a future loop mode; parsed but not yet consumed. |

## Audit engine

Audit settings nest under `audit`. [woostack-audit](/docs/skills/woostack-audit) validates this
object when it runs and hard-fails on unknown audit-local keys. The audit always runs
`simplify` and `production-readiness`, skips `architecture`, and keeps the `bugs` and `security`
safety floor from the review engine. Configured force and skip lists add to those defaults.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `audit.angles.force` | array of string | `[]` | Additional review angles to run. |
| `audit.angles.skip` | array of string | `[]` | Additional angles to skip. `simplify` cannot be skipped. |
| `audit.severity_floor` | string | `"high"` | Finding threshold: `low`, `medium`, or `high`. |
| `audit.ignore` | array of string | `[]` | Globs excluded from the synthetic audit diff. |
| `audit.chunking.max_loc` | integer ≥ 0 | `4000` | Changed-line threshold for splitting the synthetic diff into chunks. |
| `audit.report_dir` | string | `".woostack/audits"` | Repository-relative directory for audit reports. |

Root model tiers also drive [woostack-audit](/docs/skills/woostack-audit) on hosts that consume
repository model configuration. Put overrides in the root `models` namespace using flat leaves
(`models.fast`, `models.standard`, `models.deep`) or provider-specific leaves. A nested
`audit.models` block is a hard error.

## Sweep rounds

[woostack-sweep](/docs/skills/woostack-sweep) drives a stack of PRs to a clean review, looping
review → address-comments per PR.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `review_sweep.max_rounds` | integer > 0 | `3` | Maximum review→address rounds per PR before the sweep declares it blocked. Freeze the Review's zero-blocker/blocker classification before Address; thread resolution cannot erase a blocker. A changed head reruns Review when that frozen result contains a blocker (including a mixed set). Correction-only delta proof means the entire pre/post-head delta is limited solely to corrections for the exact recorded non-blocking Review findings; unrelated, partial, or unverified deltas block. A zero-blocker Address-produced head may advance without re-review only with that proof, focused verification, full reply/resolution evidence, descendant restack, and complete head/base/ancestry/thread read-back. A non-positive or non-integer value warns and falls back to `3`. |

## Commit hook

[woostack-commit](/docs/skills/woostack-commit) can run a command before it stages anything: a
formatter, linter, or test runner.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `commit.pre_commit` | string | absent (no-op) | Shell command run from the repo root before staging. A non-zero exit stops the commit; if it changes files, relevance is reassessed before staging. |

## Base branch

`base_branch` is a top-level string (not nested) naming the trunk branch that PRs target and that
worktrees are cut from.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `base_branch` | string | auto-detected | Trunk branch name. When absent, woostack resolves the `WOOSTACK_BASE_BRANCH` environment variable, then the remote's default branch, then `main`. |

## Defaults and doctor

<Callout type="info">
  Init scaffolds `models`, `review`, and `status`, then automatically adds validated
  Linear defaults when safe authenticated discovery succeeds. Missing connectivity never blocks
  local initialization. Build and Fix operate with default local run authority under
  `.woostack/tmp/runs/<run-id>/`; setting `artifacts.provider: "linear"` or `"plane"` enables optional provider mirroring (Build, Fix, and Plan).
  [woostack-doctor](/docs/skills/woostack-doctor) validates effective runtime policy; explicit live checks
  prove optional artifact connectivity.
</Callout>

## Migration notes

- `AUDIT_CONFIG_FILE` is removed: [woostack-audit](/docs/skills/woostack-audit) reads effective configuration through the canonical resolver.
- Review empty-config fallback is removed: an empty `.woostack/config.json` fails closed as malformed instead of falling back to default values.
