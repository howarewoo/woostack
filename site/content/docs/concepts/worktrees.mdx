---
title: Parallelism with worktrees
description: How woostack isolates bounded implementation work independently from artifact storage.
---

A Git worktree is a separate checkout of the same repository. It lets a task edit its own branch
without changing files in the primary checkout. A worktree does not grant scope, approval, status,
or acceptance. The
[isolated-workspace guidance](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/worktrees.md)
defines the evidence and safety outcomes: repository identity, physical collision checks, parent
ancestry, exclusive ownership, recovery, and human-owned lifecycle boundaries.

Each active bounded task has one branch, one isolated workspace, one allowed set of paths, and at
most one PR. The repository, host, or caller may supply an existing linked worktree or host-managed
linked checkout at any supported location. Woostack does not require a universal directory prefix,
branch-name recipe, creation command, adoption mode, or publication-time workspace. It never falls
back to the primary checkout.

Before dispatch, resumption, review reopen, commit, or delivery, the selected workspace is checked
against the canonical repository, filesystem path aliases, complete `git worktree list --porcelain`
inventory, local and remote branches, commits, uncommitted changes, approved parent evidence, and
canonical PR evidence. A branch cannot be checked out in two physical workspaces, and equal,
aliasing, or ancestor/descendant paths are collisions. Existing suitable workspaces can be reused;
incompatible or unassigned allocations block without deletion, reset, cleanup, takeover, or silent
relocation.

The approved task names its parent branch and retained parent SHA. Direct Git evidence verifies the
selected branch's tip and ancestry, including `git merge-base --is-ancestor` for every required
predecessor. A GitHub DAG dependent's logical prerequisites never select a Git parent by themselves.
The caller must supply one explicit parent branch/SHA containing every required predecessor change and
complete readiness evidence under the
[workspace/ancestry guidance](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/worktrees.md#repository-and-ancestry-evidence).
An unresolved join pauses that task; Execute admits a selected bounded task, not the whole DAG.

## The primary tree stays clean

<Callout type="info">
  Tracked implementation writes land only in the selected isolated workspace. The primary checkout
  remains a clean coordination point, while the host harness pins each worker to its selected
  workspace. The workspace may be outside the primary checkout or under a host-managed linked-worktree
  location; isolation and direct repository evidence are the invariant.
</Callout>

Each bounded task runs with its own workspace, branch, allowed paths, and at most one PR. Separate
tasks can proceed concurrently only when their allowed paths, branches, workspaces, and PRs do not
overlap. Before writing, each worker checks that its physical working directory is the exact Git root
it was assigned.

## Recovery and lifecycle

- After success, the calling workflow verifies the finalized commit, selected workspace cleanliness,
  and canonical PR identity when submission was requested. Publication does not create a workspace
  obligation. Host-managed, external, or user-owned workspaces remain intact unless their owner
  explicitly supplies a safe lifecycle operation.
- On failure, handoff, collision, or an unknown result, preserve the workspace and report the task,
  retained parent/ancestry evidence, worktree inventory, branch/head, uncommitted changes, first
  unverified step, and safe next action. A timeout proves neither success nor absence.
- Recovery reuses the exact retained workspace and branch only after fresh direct evidence proves
  repository identity, exclusive ownership, parent ancestry, and current delivery facts. Never adopt
  an unrelated checkout or create around a collision.

An unavailable optional GitHub read does not weaken collision or ancestry checks. A failed GitHub
delivery-note operation is reported separately and does not block delivery already verified against
local task evidence and repository state; it never grants merge authority.
