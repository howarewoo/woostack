---
title: Parallelism with worktrees
description: How woostack isolates bounded implementation work independently from artifact storage.
---

A Git worktree is a separate checkout of the same repository. It lets a task edit its own branch
without changing files in the primary checkout. A worktree does not grant scope, approval, status,
or acceptance. The
[canonical worktree contract](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/worktrees.md)
defines collision checks, parent relationships, recovery, and removal.

## One worktree per bounded task

Each active implementation task has one controller and run identity, one branch, one worktree,
one allowed set of paths, and at most one PR. Task and run IDs remain separate from optional
provider IDs and mirror records.

```text
.woostack/worktrees/tasks/<stable-task-id>
```

Before creating, resuming, reopening for review, committing, or removing a worktree, woostack checks
its expected path and task against the filesystem, `git worktree list --porcelain`, local and remote
branches, commits, uncommitted changes, Graphite parents, and GitHub PR evidence. A branch can be
checked out in at most one worktree, and all observed paths and commits must agree.

For new work, `git worktree add -b` creates the branch and checkout together. Git rejects an
existing branch, path, or checkout. Retained work resumes only when all evidence matches the same
approved task or a fully verified handoff. Partial, unrelated, or competing state stops the task.
The agent must not reset, stash, delete, adopt another checkout, or create around the collision.

The approved task names its parent branch. Direct Git evidence verifies the branch's tip, its
latest commit. When the same branch moves, Execute checks the changes against the selected task,
its dependencies, and any retained work. Unrelated changes continue without a prompt; relevant or
uncertain changes offer `Continue`, `Revise spec/plan`, or `Stop`. Ancestry safeguards still apply.
Retained work keeps its recorded start and head commits and rechecks ancestry, diff, and PR base
without silently rebasing, resetting, or recreating it.
Available CI checks are observation-only; their result or availability alone does not block.

| Task kind | Fresh branch start | Graphite parent |
| --- | --- | --- |
| Standalone task | latest compatible tip of the integration branch | integration branch |
| Independent feature root | latest compatible tip of the approved parent branch | approved parent branch |
| Dependency child | latest compatible tip/head of its declared Git parent | declared parent branch |

A changed branch identity, rewritten history, conflict, duplicate ancestry, delivery-evidence
mismatch, or missing required evidence stops the task. Titles, nearby branches, artifact links, and
task order cannot replace approved dependencies and verified Git ancestry.

## The primary tree stays clean

<Callout type="info">
  Tracked implementation writes land in the task worktree. The primary checkout remains a clean,
  stable coordination point.
</Callout>

Execute processes tasks one at a time within each local run. Separate runs can proceed concurrently
only when their allowed paths, branches, worktrees, and PRs do not overlap. Dependent tasks follow
their declared Git parent. Before writing, each worker checks that its physical working directory
is the exact Git root it was assigned.

## Teardown and recovery

- After success, the controller verifies the finalized commit, clean task worktree, and canonical
  PR identity when submission was requested. It removes only the exact task worktree. The branch,
  commits, PR, and remote evidence remain.
- On failure, handoff, or an unknown result, keep the worktree. Report the task and run, expected
  path, worktree inventory, branch ancestry, uncommitted changes, first unverified step, and safe next
  action. A timeout proves neither success nor absence.
- When reopening for review, attach only the verified existing branch and head. Its expected path
  must be free and the branch checked out nowhere else. Never adopt an unrelated checkout.

Optional provider failure does not weaken collision or ancestry checks. A failed mirror operation
does not block delivery that has been verified against the local run and repository.
