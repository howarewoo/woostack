---
title: Parallelism with worktrees
description: How woostack isolates bounded implementation work without requiring Linear.
---

Worktrees isolate tracked writes. They do not own scope, approval, status, or acceptance. The
[canonical worktree contract](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/worktrees.md)
defines collision checks, ancestry, recovery, and teardown.

## One worktree per bounded task

Each active task has one controller/run identity, one branch, one worktree, one allowed surface, and
at most one implementation PR. A task may be keyed by an exact caller-supplied Linear issue UUID,
but Linear is optional; artifact-free runs use a stable run/task UUID.

```text
.woostack/worktrees/tasks/<stable-task-id>
```

An atomic gitignored claim under `.woostack/worktrees/.registry/<task-id>/claim.json` prevents
competing local checkouts. It contains only recovery facts such as the task ID, run/controller,
branch, path, base, and start commit. It is disposable administration, not a development record.

The start point comes from the approved dependency plan and verified Git ancestry:

| Task kind | Branch start | Graphite parent |
| --- | --- | --- |
| Standalone task | exact integration-base commit | integration branch |
| Independent feature root | frozen base commit | frozen base branch |
| Dependency child | finalized head of its declared Git parent | declared parent branch |

Titles, nearby branches, optional artifact relations, and task order do not substitute for declared
dependencies and Git ancestry.

## The primary tree stays clean

<Callout type="info">
  Tracked implementation writes land in the task worktree. The primary checkout remains a clean,
  stable coordination point.
</Callout>

Independent roots may run concurrently only when their declared dependencies, responsibility
surfaces, branches, worktrees, and PRs are disjoint. Dependent tasks follow their declared Git
parent. Subagents receive the exact path and verify that their physical working directory matches
the Git top level before writing.

## Teardown and recovery

- **Success:** after commit, push, and canonical PR identity read back, remove the exact worktree and
  registry claim. Branch, commits, PR, and remote evidence remain.
- **Failure or unknown:** preserve the worktree and claim. Report task ID, path, branch, observed
  boundary, and safe next action; a timeout proves neither success nor absence.
- **Review reopen:** reattach only the existing verified branch/head in a fresh collision-free
  worktree; never invent an unrelated checkout.

Optional artifact synchronization occurs after repository evidence exists. Missing provider access
never weakens the local collision or ancestry checks.
