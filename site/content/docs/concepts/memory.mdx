---
title: Memory
description: "How woostack recalls local reusable knowledge without confusing it with Linear development state."
---

woostack keeps two local knowledge stores under `.woostack/`. Memory is recalled narrowly by
scope; wisdom is loaded wholesale. Both preserve reusable learning across sessions, but neither is
feature state or development authority. Linear is the only development-record authority. Git and
GitHub own code and PR truth.

The canonical [memory contract](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/memory.md)
and [wisdom contract](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/wisdom.md)
own their formats and curation rules. The
[Linear authority](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/artifact-backends.md)
owns managed identity, lifecycle, assignment, decisions, and acceptance.

## Two knowledge stores

- **`memory/`** holds scoped, per-fact notes. Recall loads only notes whose `scope` glob matches
  the files in play, plus bounded linked and tag-related notes. A small working set pulls in a small
  knowledge set.
- **`wisdom/`** holds a compact set of generalized, cross-cutting findings. Skills that need wisdom
  load the complete store rather than scope-matching it.

<Callout type="info">
  Knowledge can advise an implementation; it cannot authorize one. A note cannot establish scope,
  ownership, dependencies, phase, approval, progress, or acceptance. Consumers first verify the
  exact Linear issue/project context through official MCP and independently verify Git/GitHub facts,
  then use relevant memory and wisdom as advisory context.
</Callout>

## Stable provenance, never shadow authority

New memory notes cite the most specific stable `linear://project/<uuid>` or
`linear://issue/<uuid>` identity. Notes recorded from review use the exact `pr-<n>` marker or
`address-comments`. Linear documents, titles, slugs, issue keys alone, and local specification,
plan, or fix paths are not new provenance. Historical Markdown source values may remain only as
migration input and never authorize current work.

## Diagnostic reports are evidence, not state

Sanitized local diagnostic reports, including response, QA, audit, and evaluation output, are
non-authoritative evidence. They may identify a pattern worth investigating or corroborate a
knowledge claim, but they cannot create a work item, change lifecycle state, grant implementation
permission, or prove acceptance. Raw provider evidence remains transient and outside recall.
Sanitized response reports never enter `MEMORY.md` and are never pruned as curation scratch.
Dream can read them as corroborating diagnostics; recall never reads them.

[woostack-dream](/docs/skills/woostack-dream) may consolidate a recurring, independently
corroborated pattern into wisdom through its approval gate. One report or incident is never enough,
and remote development content remains context rather than a curation target.

## When skills load knowledge

| Skill | Reads memory (scoped) | Reads wisdom (wholesale) | Moment |
| --- | :---: | :---: | --- |
| [woostack-ideate](/docs/skills/woostack-ideate) | — | ✓ | exploring reusable design constraints |
| [woostack-plan](/docs/skills/woostack-plan) | — | ✓ | before recording implementation increments in Linear |
| [woostack-debug](/docs/skills/woostack-debug) | ✓ | ✓ | surfacing known gotchas and failure-class hypotheses to test |
| [woostack-review](/docs/skills/woostack-review) | ✓ | ✓ | before advisory angle workers inspect the verified diff |
| [woostack-execute](/docs/skills/woostack-execute) | writes | — | distilling reusable learning after an implemented increment |
| [woostack-dream](/docs/skills/woostack-dream) | reads & curates | reads & writes | consolidating corroborated knowledge |
| [woostack-status](/docs/skills/woostack-status) | — | — | deriving a fresh board from official MCP and Git/GitHub |

Two skills feed the stores:

```text
woostack-execute        ── distill ─────► memory/   (scoped reusable learning)
woostack-dream          ── consolidate ─► wisdom/   (generalized cross-cutting knowledge)

ideate · plan · review · debug  ── load wholesale ─► wisdom/
debug · review                  ── scope-match ────► memory/
```

Recall is computed outside the prompt: `recall.sh` performs the scope match plus bounded wikilink
and tag expansion, while `build-index.sh` keeps `memory/MEMORY.md` to one line per note. See
[Context management](/docs/concepts/context-management) for how that keeps working context small
without weakening the authority boundary.
