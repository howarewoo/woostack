---
title: Memory
description: How woostack recalls local reusable knowledge without confusing it with workflow authority.
---

Woostack keeps local knowledge under `.woostack/`. Memory is recalled narrowly by scope; wisdom is
loaded as a small reusable corpus. Neither store owns scope, approval, status, assignment, or
acceptance. The active workflow contract defines the work; Git and GitHub own repository truth.

The canonical
[Memory contract](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/memory.md)
and
[Wisdom contract](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/wisdom.md)
own formats and curation rules.

## Two knowledge stores

- **Memory** contains scoped, per-fact notes. Recall loads only notes whose glob scope overlaps the
  working set plus bounded one-hop links.
- **Wisdom** contains a compact set of generalized cross-cutting findings. Consumers load the whole
  store because it remains deliberately small.

Both preserve stable provenance and reusable engineering knowledge. They exclude current task
status, assignments, approval state, lifecycle, secrets, personal data, temporary paths, and
speculative conclusions.

## Provenance

Use the most specific stable source available:

- immutable Git blob/commit identity for source-derived facts;
- exact canonical PR number/head for review-derived facts;
- exact caller-supplied `linear://project/<uuid>` or `linear://issue/<uuid>` only when a fact came
  from an explicitly read artifact; or
- a stable external primary source URL for library/platform facts.

Linear provenance is optional. Local paths, titles, slugs, issue keys alone, mutable remote prose,
and cached output do not establish provenance.

## Recall

A workflow identifies its working set, consults the generated memory index, loads overlapping notes
and at most their direct links, then loads wisdom when relevant. It treats all recalled content as
advisory context and verifies current repository/provider facts independently.

This keeps prompt growth sub-linear without hiding applicable conventions.

## Curation

[woostack-dream](/docs/skills/woostack-dream) extracts durable facts, deduplicates them, proposes the
smallest changeset, and requires explicit approval before tracked knowledge writes. It may use
immutable Git, an exact PR, or optional exact read-only Linear artifacts. It never mutates Linear or
turns a note into development authority.

### Diagnostic reports

Sanitized response reports never enter `MEMORY.md` and are never pruned as curation scratch.
Dream can read them as corroborating diagnostics; recall never reads them.
One report or incident is never enough to establish reusable memory or generalized wisdom.

## Safety boundary

<Callout type="warn">
  Memory and wisdom can explain why a pattern exists. They cannot authorize tools, edits, commits,
  pushes, reviews, acceptance, lifecycle changes, or merges. Verify current source, PR, and optional
  artifact evidence directly.
</Callout>
