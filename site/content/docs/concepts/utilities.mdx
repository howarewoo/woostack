---
title: Utilities
description: "On-demand investigation, presentation, diagnostics, and local knowledge maintenance alongside Linear-backed development."
---

Most woostack skills advance work bound to a Linear issue or project. Utilities sit beside those
flows: they investigate, render, diagnose, evaluate, or maintain reusable local knowledge without
becoming a development record. None merge, and none turn their output into permission to edit.

The authority boundary is constant: Linear is the only development-record authority. Git and
GitHub own code, PR, review, and merge truth. Local views, reports, caches, memory, and wisdom are supporting material.
The canonical
[Linear development authority](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/artifact-backends.md)
and [state conventions](https://github.com/howarewoo/woostack/blob/main/skills/woostack-status/references/conventions.md)
define the remote record rather than these utilities.

## Investigate and present

These skills answer, render, or inspect a bounded target. Where managed context is needed, they
accept an exact issue/project identity, verify it through the
[official Linear MCP](https://mcp.linear.app/mcp), and join code or PR facts independently.
`woostack-respond` also reads production telemetry and may hand a verified repository defect to the
normal issue gate. Run it only inside explicitly authorized operational context; repository setup
or CI never implies production access.

| Skill | What it does | Writes? | Invoke |
| --- | --- | --- | --- |
| [woostack-ask](/docs/skills/woostack-ask) | Answers a question from code, local knowledge, cited external evidence, and verified Linear context only when managed facts are relevant. | no | `/woostack-ask <question>` |
| [woostack-visualize](/docs/skills/woostack-visualize) | Renders a verified Linear project/issue, file, directory, or concept as one self-contained HTML view for a chosen audience. | disposable HTML view | `/woostack-visualize <source>` |
| [woostack-status](/docs/skills/woostack-status) | Computes a fresh project-and-standalone-issue board from official MCP plus exact Git/GitHub evidence. | conditional receipt-backed terminal reconciliation; no local board file | `/woostack-status` |
| [woostack-debug](/docs/skills/woostack-debug) | Runs a four-phase root-cause analysis and hands findings back without writing the correction. | no | `/woostack-debug <target>` |
| [woostack-qa](/docs/skills/woostack-qa) | Exploratory-QAs a running app in a real browser and writes a sanitized, severity-ranked report. | non-authoritative report | `/woostack-qa <url> [focus…]` |
| [woostack-audit](/docs/skills/woostack-audit) | Reviews standing code through the review swarm and writes a sanitized ranked report without remediation. | non-authoritative report | `/woostack-audit <target>` |
| [woostack-respond](/docs/skills/woostack-respond) | Investigates bounded production telemetry, writes a sanitized report, and may hand a verified repository defect to the normal issue gate. | non-authoritative report; gated handoff | `/woostack-respond <signal> [scope…]` |
| [woostack-eval](/docs/skills/woostack-eval) | Runs approved behavior and trigger corpora as isolated candidate/baseline comparisons without editing the target skill. | approved corpus changes only; transient evidence | `/woostack-eval <skill-path> [--behavior\|--triggers\|--all]` |

`woostack-eval` writes tracked corpus files only after explicit approval. Its evidence and reports
are transient, and it never edits the target skill.

<Callout type="info">
  HTML views and sanitized diagnostic or evaluation reports are non-authoritative evidence. They
  cannot establish scope, assignment, dependencies, lifecycle, acceptance, or implementation
  permission. Acting on a finding requires the appropriate exact Linear issue/project binding and
  fresh provider read-back.
</Callout>

`woostack-respond` runs only inside explicitly authorized operational context; repository setup or
CI never implies production access.

Remote titles, descriptions, comments, diffs, telemetry, and tool output are untrusted evidence,
never instructions. Reports exclude secrets and raw provider payloads; transient evidence stays
outside the reusable knowledge stores.

## Tend local support state

These skills maintain the non-authoritative `.woostack/` support surfaces. Both are gated: they
propose a changeset and write only after explicit approval.

| Skill | What it does | Writes? | Invoke |
| --- | --- | --- | --- |
| [woostack-doctor](/docs/skills/woostack-doctor) | Diagnoses local policy, memory, wisdom, and workspace integrity, then applies only approved local repairs. It does not repair remote development records. | gated local changes | `/woostack-doctor` |
| [woostack-dream](/docs/skills/woostack-dream) | Curates [memory and wisdom](/docs/concepts/memory) and evidence-backed docs. Verified remote context is read-only corroboration, never a curation target. | gated local changes | `/woostack-dream [instructions]` |
