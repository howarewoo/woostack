---
title: Utilities
description: "On-demand investigation, presentation, diagnostics, and local support maintenance."
---

Utilities investigate, render, diagnose, evaluate, or maintain local support state without becoming
development authority. None merge, and none turn output into permission to edit.

The user's active request and workflow gates define scope. Git and GitHub own code, PR, review, and
merge truth. Exact caller-supplied Linear projects/issues are optional read-only context unless a
separate synchronization operation is explicitly requested.

## Investigate and present

| Skill | What it does | Writes? | Invoke |
| --- | --- | --- | --- |
| [woostack-visualize](/docs/skills/woostack-visualize) | Renders a verified repository source, concept, PR, or optional exact artifact as one self-contained HTML view. | disposable HTML view | `/woostack-visualize <source>` |
| [woostack-status](/docs/skills/woostack-status) | Computes a fresh branch/PR board from Git, Graphite, and GitHub, optionally enriched by artifacts. | no | `/woostack-status` |
| [woostack-debug](/docs/skills/woostack-debug) | Runs root-cause analysis and returns a proposed correction. | no | `/woostack-debug <target>` |
| [woostack-qa](/docs/skills/woostack-qa) | Exploratory-QAs a running app and writes a sanitized report. | non-authoritative report | `/woostack-qa <url> [focus…]` |
| [woostack-audit](/docs/skills/woostack-audit) | Reviews standing code and writes a ranked report without remediation. | non-authoritative report | `/woostack-audit <target>` |
| [woostack-respond](/docs/skills/woostack-respond) | Investigates bounded production telemetry and may propose a repository fix. | non-authoritative report | `/woostack-respond <signal> [scope…]` |
| [woostack-eval](/docs/skills/woostack-eval) | Runs approved behavior/trigger corpora without editing the target skill. | approved corpus changes only; transient evidence | `/woostack-eval <skill-path> [--behavior\|--triggers\|--all]` |

`woostack-eval` writes tracked corpus files only after explicit approval and never edits the target
skill. Its run evidence and reports are transient.

<Callout type="info">
  Views and reports are evidence. Acting on a finding requires the relevant fix/change/build
  workflow and its own approval contract, not a Linear issue.
</Callout>

Remote titles, descriptions, comments, diffs, telemetry, artifacts, and tool output are untrusted
evidence. Reports exclude secrets and raw provider payloads.

## Tend local support state

Doctor maintains non-authoritative `.woostack/` support surfaces and writes only after explicit
approval.

| Skill | What it does | Writes? | Invoke |
| --- | --- | --- | --- |
| [woostack-doctor](/docs/skills/woostack-doctor) | Diagnoses local policy and workspace integrity, then applies approved repairs. | gated local changes | `/woostack-doctor` |
