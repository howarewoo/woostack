Woostack separates product authority from repository delivery evidence. Local run manifests under
`.woostack/tmp/runs/<run-id>/` own the current specification and execution contracts for builds and
post-diagnosis fixes (with optional Linear or Plane mirroring: `artifacts.provider: "linear"` or `artifacts.provider: "plane"`).
Git and GitHub own source, branches, commits, pull requests, reviews, and merge evidence.

## Choose the smallest workflow

| Shape | Commands | Active contract | Provider mirror behavior |
| --- | --- | --- | --- |
| Bounded bug or regression | [woostack-fix](/docs/skills/woostack-fix) | proved root cause plus plain specification and direct-issue plan | local run manifest, direct increment contracts, dependencies (optional Linear or Plane mirror) |
| Bounded non-bug change | [woostack-change](/docs/skills/woostack-change) | one explicit goal/contract | none |
| Multi-increment feature | [woostack-build](/docs/skills/woostack-build) | plain specification plus direct-issue graph | local run manifest, direct increment contracts, dependencies (optional Linear or Plane mirror) |
| Greenfield codebase | [woostack-bootstrap](/docs/skills/woostack-bootstrap) | complete approved design | exact artifact or explicit persistence request only |

Route by work shape. Development records do not turn ambiguous scope into a complete contract or
replace direct repository evidence.

## The plain-artifact build loop

Multi-increment work follows one fixed chain:

```text
allocate/resume local run and admit exact baseline (if mirroring) →
draft Ideate/Harden locally →
write `project-spec.md` (and optional bounded mirror sync) →
draft Plan/Harden locally →
write `execution-plan.md` (and optional bounded mirror sync) →
retain run artifacts →
present verified run handoff
```

Build and project-backed Fix write plain Markdown `project-spec.md` and `execution-plan.md` working
documents directly under `.woostack/tmp/runs/<run-id>/`. During each drafting phase there are no
intermediate provider cycles. When `artifacts.provider: "linear"` or `artifacts.provider: "plane"`, one
bounded cycle mirrors Build and Fix artifacts to the configured provider; mirror failure is recorded in the manifest and is nonblocking
for local authority.
After both files are written, Build/Fix display the exact run ID, readable artifact paths, stable task
mappings, dependencies, planning parent branch, planning parent tip, and
`/woostack-execute --run <exact-run-id>`. A mirrored project URL/UUID is evidence only, not an
alternate Build/Fix handoff. A body-free handoff Ask offers exactly `Stop here`, `Execute`, and
`Abandon`: Stop here returns without mutation, Execute invokes normal Execute once, and Abandon
records abandonment without dispatch. Unknown or custom input fails closed and asks again.

When the integration parent tip changes after planning, Execute reports the difference and asks
the user to choose `Continue`, `Revise spec/plan`, or `Stop` before any source mutation.

The shared [Local run artifact and provider mirror contract](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/artifact-backends.md#minimal-resumable-manifest-schema)
is the detailed authority for the run manifest, plain Markdown artifacts, mirror synchronization,
retention, and unchanged Execute reads.

## Execution invariants

- One independently shippable increment maps to at most one PR.
- Execute accepts `--run <exact-run-id> [--recheck]`, `--project <...>`, or `--issue <...>`. Sequential
  execution within each run; distinct runs in isolated worktrees may run concurrently when
  responsibility surfaces do not collide.
- Each active task has one controller identity, branch, collision-safe worktree, allowed surface,
  and current head.
- The implementation worker returns an uncommitted diff and evidence. The controller performs
  specification and quality review before authorizing commit/PR delivery.
- Graphite preserves stack ancestry. GitHub proves PR/head/base/check/review/merge state.
- Every workflow stops on scope, ancestry, collision, evidence, or review drift. No workflow merges.

## Canonical local records and optional Linear and Plane mirroring

Build and project-backed Fix operate with canonical persistent local run authority under
`.woostack/tmp/runs/<run-id>/` by default (`artifacts.provider: "local"` or omitted). Supplying `--project` when
`artifacts.provider` is not configured for mirroring fails closed immediately.

When `artifacts.provider: "linear"`, local artifacts mirror to one Linear project containing the
complete specification, direct increment issues, and native issue dependencies. There is no parent plan
issue or child containment. `woostack-change` never contacts Linear.

When `artifacts.provider: "plane"`, Build and Fix mirror artifacts to one Plane project containing the complete
specification, `N` parentless direct work items (`parent = null`), and `N-1` strict blocking relations.
Project admission requires mandatory official Plane MCP project-label capabilities when `artifacts.plane.projectLabels`
is configured, flattens completely paginated workspace project labels with null terminal cursors, and unions
configured labels with existing project labels (preserving unrelated labels). If the official Plane MCP lacks
project-label operations, persistence fails closed before project mutation. Optional provider writers (Bootstrap and Commit) are unsupported in this increment and fail closed.

The manifest is the canonical local run authority. Standalone Plan remains distinct: it keeps its direct
project-graph synchronization and independent read-back unchanged for Linear or Plane, without either Build/Fix approval
gate.

Explicit abandonment sets `status: "abandoned"` in the run manifest and retains all run artifacts in
`.woostack/tmp/runs/<run-id>/` without mutating a mirrored Linear or Plane project. Standalone Plan closes its
existing project as canceled after independent read-back. Handoff, replanning, and blockers leave the
project open.
## Authority boundaries

| Surface | Authority |
| --- | --- |
| User request and decisions | initiates the selected workflow and authorizes decisions |
| Local run manifest (`.woostack/tmp/runs/<run-id>/`) | current fix/build product scope, plans, contracts, and execution state (mirrored to Linear or Plane when configured) |
| Git and GitHub | source, ancestry, commits, PRs, checks, reviews, merge evidence |
| Graphite | stack and branch operations |
| Audit, QA, response reports | sanitized non-authoritative diagnostic evidence |
The [Hermes guide](/docs/hermes) documents how an external engineer can review harness evidence
without receiving implementation authority.
