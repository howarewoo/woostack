The user decides the product and authorizes work. Git and GitHub show what was delivered.
Plan produces a verified native issue graph; Orchestrate may also consume a complete readable
tracker and independently read its executable issues when native relationship metadata is absent,
partial, or unavailable. Implementation remains a separate explicit workflow.

## Workflow scope

| Shape | Commands | Active contract | Provider/input behavior |
| --- | --- | --- | --- |
| Feature or proved defect needing several increments | [woostack-prepare](/docs/skills/woostack-prepare) | complete user-verified specification, evidence-bound diagnosis when applicable, and Plan's read-back GitHub graph | no local run or mirror; exact parent or Project selector belongs to Plan |
| Specification elicitation | [woostack-ideate](/docs/skills/woostack-ideate) | complete plain user-verified decisions | no provider or run required |
| Repository reconciliation | [woostack-harden](/docs/skills/woostack-harden) | complete plain candidate after bounded evidence checks | no provider or run required |
| Approved issue publication | [woostack-plan](/docs/skills/woostack-plan) | one exact GitHub parent/child or Project graph with native prerequisite edges | direct host-authenticated GitHub reads/writes; no mirror required |
| Bounded enhancement, refactor, tests, or authorized correction | [woostack-execute](/docs/skills/woostack-execute) | one complete bounded contract from inline input or one canonical task-bearing issue, and one PR | goal-only is provider-free; an exact issue is read-only task input and Commit association |
| Greenfield codebase | [woostack-bootstrap](/docs/skills/woostack-bootstrap) | complete approved design | exact target only; direct GitHub Project publication is explicit |

The shape of the work determines the workflow. Historical development records cannot turn ambiguous
scope into a complete contract or replace direct repository evidence.

## Planning and informed approval

Prepare is the thin composition for a feature or defect. A defect first uses [Debug](/docs/skills/woostack-debug)
or independently revalidates a complete diagnosis: observed and expected behavior, causal chain,
immutable source/runtime evidence, correction boundary, risks, and verification. Missing proof blocks;
Prepare never guesses a correction.

Public [Ideate](/docs/skills/woostack-ideate) collects decisions the user verifies and returns
complete plain content. Public [Harden](/docs/skills/woostack-harden) checks supplied specification or
candidate-plan content against bounded repository evidence and raises each material discrepancy before
changing it. Both accept explicit repository/evidence identity without a Prepare run. Complete input
may start at the relevant phase, so settled approvals are not repeated.

Plan divides the work into increments, each small enough for one PR. It records outcomes, scope,
acceptance criteria, verification, risks, explicit technical prerequisites, and parent-selection
policy. It does not prescribe every coding step or estimate changed lines. [GitHub plans](/docs/configuration/artifacts/github#identities-hierarchy-and-graph)
support technical dependency DAGs in explicit Project mode and parent-issue mode
(`--parent-issue new` or an exact parent issue URL, exclusive with `--project`). Plan's
parent-issue mode needs the exact canonical repository and native relationship capabilities; it does
not require a provider selector, Project, mirror, or Build/Fix run. Direct and composed Plan use the
same public Harden reconciliation and publisher. Its native parent hierarchy only groups the plan and
is distinct from `blocked-by` edges and Git branch ancestry; the parent is never a task, dependency
endpoint, execution, or PR, and unsupported nested or partial hierarchy fails closed. A complete
readable tracker index can remain useful to Orchestrate when those native relationships are absent,
but that declared handoff is not successful native Plan publication.

Execute accepts one selected bounded task under its [admission contract](/docs/skills/woostack-execute#admit-one-task), not a whole plan.
An explicit [Orchestrate](/docs/skills/woostack-orchestrate) invocation interprets the complete
planning handback or other understandable work context. It resolves the canonical repository,
issue/task identities, executable tasks, and a bounded technical DAG with provenance, then selects
and summarizes a model-chosen single-parent execution forest before allocation. Added ordering is
compatibility evidence, not native relationship evidence; technical prerequisites remain visible
separately, useful parallelism is retained, and effective prerequisites govern readiness and repair
propagation. Issue, issue-list, and Project arguments are convenience hints, not an exhaustive
admission taxonomy; a complete tracker index can establish declared membership without native links,
while every selected issue and contract still needs independent reads. For Orchestrate, a Project is
included only when explicitly selected; its status lifecycle is used only when that selection requests
status mutation, and inferred edges are not published.

Plan is the sole issue publisher. It independently reads every parent, child, hierarchy, and edge
back. A partial Plan graph preserves exact identities and resumes at the first unproved Plan boundary;
it is not a complete native publication. A declared tracker handoff can still be independently read
and scheduled by Orchestrate when its selected issues and contracts are complete. Prepare reports the
complete planning handback and may include `/woostack-orchestrate --issue <verified-parent-url>` as a
convenience suggestion, but never invokes it.

## Execution invariants

- Each increment fits at most one PR.
- Execute takes one complete bounded task per invocation: pass inline bounded input, one canonical
  task-bearing issue URL, or inline instructions with an optional exact canonical GitHub issue URL.
  Retired `--run`, `--project`, and `--recheck` inputs are rejected (see
  [Execute](/docs/skills/woostack-execute#retired-inputs)).
- Each bounded task runs its own worktree, branch, allowed paths, and PR. Separate tasks may proceed
  concurrently only when their paths, branches, worktrees, PRs, and responsibilities do not overlap.
- Focused checks, a smoke test of changed behavior, and comparison against the approved task precede
  delivery. Orchestrate requires delivery-capable Execute workers and independent post-submission
  validation before releasing dependents.
- Git and GitHub prove parent-child branch relationships, PRs, commits, reviews, and merge state.
  Graphite supplies additional stack evidence only when selected. Required repository checks remain
  mandatory delivery gates; non-required available CI checks are observation-only.
- Unresolved scope, ancestry, collision, required-evidence, or review conflicts stop the workflow.
  Agents never merge, mark a PR ready, enable auto-merge, or queue a PR for merge.

## Retained records and authority boundaries

Existing `.woostack/tmp/runs/<run-id>/` artifacts from retired planning wrappers remain readable
historical user data and are never migrated or mutated. A supplied record is evidence only after exact
identity, complete content, and freshness validation. It does not authorize publication, assignment,
implementation, or ownership. Legacy managed-provider records remain opaque; direct GitHub publication
uses only its exact selected scope.

| Surface | Authority |
| --- | --- |
| Prepare/Ideate/Harden plain packets | complete planning content and evidence handbacks; no source or issue authority |
| Plan's verified GitHub graph | publication identity, child contracts, and native prerequisite read-back |
| Git and GitHub | source, ancestry, commits, PRs, checks, reviews, merge evidence |
| Graphite (optional) | stack and branch operations when explicitly selected or already managed |
| Audit, QA, response reports | sanitized non-authoritative diagnostic evidence |

The [Hermes guide](/docs/hermes) documents how an external engineer can review harness evidence
without receiving implementation authority.
