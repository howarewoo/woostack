description: The two-gate local-authority build loop, optional Linear mirroring, and bounded one-PR routes.

Woostack separates product authority from repository delivery evidence. Local run manifests under
`.woostack/tmp/runs/<run-id>/` own the current specification and execution contracts for builds and
post-diagnosis fixes, with optional Linear mirroring (`linear.saveArtifacts: true`). The responsible
user's approval event clears only the matching exact gate-file hash. Git and GitHub own source,
branches, commits, pull requests, reviews, and merge evidence.

## Choose the smallest workflow

| Shape | Commands | Active contract | Linear behavior |
| --- | --- | --- | --- |
| Bounded bug or regression | [woostack-fix](/docs/skills/woostack-fix) | proved root cause plus approved project-spec and direct-issue revisions | local run manifest, direct increment contracts, dependencies (optional Linear mirror) |
| Bounded non-bug change | [woostack-change](/docs/skills/woostack-change) | one explicit goal/contract | none |
| Multi-increment feature | [woostack-build](/docs/skills/woostack-build) | approved project-spec revision plus approved direct-issue graph | local run manifest, direct increment contracts, dependencies (optional Linear mirror) |
| Greenfield codebase | [woostack-bootstrap](/docs/skills/woostack-bootstrap) | complete approved design | exact artifact or explicit persistence request only |

Route by work shape. Development records do not turn ambiguous scope into a complete contract or
replace direct repository evidence.

## The two-gate build loop

Multi-increment work follows one fixed chain:

```text
allocate/resume local run and admit exact baseline (if mirroring) →
draft Ideate/Harden locally →
stream complete verified `project-spec.md` bytes and full identity (or a verified same-process
byte-complete unified diff with old/new identities) immediately before a body-free `Accept`/`Abandon`
Ask → record local approval record (and optional bounded mirror sync) → draft Plan/Harden locally →
stream complete verified `execution-plan.md` bytes and full identity (or a verified same-process
byte-complete unified diff with old/new identities) immediately before a body-free `Accept`/`Abandon`
Ask → record local approval record (and optional bounded mirror sync) → retain run artifacts →
present verified run handoff
```

The only content gates are deterministic project-spec-file approval and execution-plan-file
approval. Each stream carries the complete exact Markdown bytes and full identity immediately before
its body-free Ask; a same-process revision may carry only one independently verified byte-complete
unified diff with old/new full-file identities. Acceptance records the local raw-hash approval record
(`projectSpecApprovalRecord` or `executionPlanApprovalRecord`). During each gated drafting phase there
are no intermediate provider cycles. When `linear.saveArtifacts: true`, one bounded cycle mirrors
approved artifacts to Linear; mirror failure is recorded in the manifest and is nonblocking for local
authority.

After gate 2, Build/Fix display the exact run ID, both local approval records and gate-file hashes,
stable task mappings, dependencies, approved parent branch, last admitted tip, and
`/woostack-execute --run <exact-run-id>`. A mirrored project URL/UUID is evidence only, not an
alternate Build/Fix handoff. A body-free handoff Ask offers exactly `Stop here`, `Execute`, and
`Abandon`: Stop here returns without mutation, Execute invokes normal Execute once, and Abandon
records abandonment without dispatch. Unknown or custom input fails closed and asks again.

The shared [Local run artifact and provider mirror contract](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/artifact-backends.md#run-scoped-gated-draft-manifest)
is the detailed authority for the run manifest, owner-only gate files, streamed artifact bytes and
identity, same-process revision diffs, body-free approval Asks, raw-hash approval records, retention,
and unchanged Execute reads. Material updates to approved gate files or specifications invalidate the
matching gate.

## Execution invariants

- One independently shippable increment maps to at most one PR.
- Execute accepts `--run <exact-run-id> [--recheck]`, `--project <...>`, or `--issue <...>`. Sequential
  execution within each run; distinct runs in isolated worktrees may run concurrently when
  responsibility surfaces do not collide.
- Each active task has one controller identity, branch, collision-safe worktree, allowed surface,
  and current head.
- The implementation worker returns an uncommitted diff and evidence. The controller performs
  specification and quality review before authorizing commit/PR delivery.
- Graphite preserves stack ancestry. GitHub proves PR/head/base/check/review/merge state.
- Every workflow stops on scope, ancestry, collision, evidence, or review drift. No workflow merges.

## Canonical local records and optional Linear mirroring

Build and project-backed Fix operate with canonical persistent local run authority under
`.woostack/tmp/runs/<run-id>/` by default (`linear.saveArtifacts: false`). Supplying `--project` when
`linear.saveArtifacts` is false or absent fails closed immediately.

When `linear.saveArtifacts: true`, approved local artifacts mirror to one Linear project containing the
complete specification, direct increment issues, and native issue dependencies. There is no parent plan
issue or child containment. `woostack-change` never contacts Linear.

The manifest is the canonical local run authority. Standalone Plan remains distinct: it keeps its direct
project-graph synchronization and independent read-back unchanged, without either Build/Fix approval
gate.

Explicit abandonment sets `status: "abandoned"` in the run manifest and retains all run artifacts in
`.woostack/tmp/runs/<run-id>/` without mutating a mirrored Linear project. Standalone Plan closes its
existing project as canceled after independent read-back. Handoff, replanning, and blockers leave the
project open.

## Authority boundaries

| Surface | Authority |
| --- | --- |
| User request | initiates the selected workflow |
| Responsible-user approval event | exact fix/build gate-file raw-hash approval record |
| Local run manifest (`.woostack/tmp/runs/<run-id>/`) | current fix/build product scope, plans, contracts, and local approval records (mirrored to Linear when `linear.saveArtifacts: true`) |
| Git and GitHub | source, ancestry, commits, PRs, checks, reviews, merge evidence |
| Graphite | stack and branch operations |
| Audit, QA, response reports | sanitized non-authoritative diagnostic evidence |
The [Hermes guide](/docs/hermes) documents how an external engineer can review harness evidence
without receiving implementation authority or changing the approval gates.
