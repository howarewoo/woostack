title: Overview
description: "woostack's local run authority, optional Linear, Plane, and GitHub mirror records, delivery boundaries, and context management."
---

woostack uses explicit user decisions, separate workspaces for implementation, and independent
review. A bounded fix or change fits one pull request (PR). Build and project-backed Fix keep the
user-verified specification, ordered plan, and recovery state locally. Optional provider mirrors
copy those records to Linear, Plane, or GitHub. Git and GitHub show the actual code and PR state.

The [core concepts](/docs/concepts) explain who can authorize work and which records prove its
results. The [workflow maps](/docs/concepts/workflows) help you choose and run a workflow.
[woostack-reflect](/docs/skills/woostack-reflect) looks for reusable instruction improvements in a
fixed snapshot of the current conversation. It directs each suggestion to the file or skill that
owns the rule. Its report, like other diagnostic reports, does not authorize changes.
