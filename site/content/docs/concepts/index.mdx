woostack rests on two operational ideas. A feature moves through a **gated build loop** so quality
is enforced by structure, not vigilance. Every step also practices **context management**: the
agent's working context holds only what the step needs, so it reasons better and runs longer.
Across both sits a cross-cutting engineering tenet: write the least code that safely works.
Worktrees and the status board keep parallel work and collaboration cheap on top. The pages below
take each concept on its own.
