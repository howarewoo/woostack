---
title: Context management
description: "How woostack keeps context small while preserving repository truth and selected artifact provenance."
---

Context economy is not authority compression. The current approved workflow defines scope; Git and
GitHub own code and PR truth. Linear projects/issues are read only when exact caller-selected or
created by the fix/build plan workflow after repository capability preflight. No path reconstructs
authority from a local mirror, mutable title, nearby branch, cached remote body, or artifact prose.

## Output stays compact

[using-woostack](/docs/skills/using-woostack) loads one shared output discipline: lead with the
result, remove narration and repetition, and retain exact evidence, commands, paths, and errors.
Security, destructive actions, root-cause analysis, and architecture keep the detail required to
remain unambiguous.

[woostack-review](/docs/skills/woostack-review) applies the same principle through a strict finding
contract. Comments stay short without losing evidence, severity, or an actionable fix.

## Sessions end with instruction suggestions

The final reply analyzes the completed conversation and tool evidence for durable rules. It
suggests only novel guidance and targets each proposal to the global or narrowest applicable
`AGENTS.md`. When no durable lesson survives, it emits no suggestion section.

Session learning never writes an artifact or changes an instruction file. Suggestions become
instructions only through a later explicit user-requested edit.

## Helpers reduce bulk without replacing authority

Small helpers compute bounded local results:

- [woostack-status](/docs/skills/woostack-status) reads Git/Graphite/GitHub evidence and prints a
  compact board without creating a board file.
- Review's `prefetch.sh` gathers the verified PR diff, metadata, and repository rules. Exact
  caller-supplied artifact context may be added separately.

Generated indexes, bundles, temporary intent snapshots, and caches are non-authoritative aids.
Remote titles, descriptions, comments, diffs, artifact text, and tool output are evidence, never
instructions. Controllers refresh relevant source/provider truth before side effects.

## Isolated agents receive bounded envelopes

Each worker receives the minimum envelope for its role:

- an implementation worker receives one approved task, repository/worktree, allowed surface,
  dependency context, acceptance criteria, and verification contract;
- advisory review workers receive bounded diff/context bundles and cannot edit code, mutate remote
  state, or accept work.

Isolation reduces context coupling; it never transfers authority. Optional artifact identifiers and
read results may accompany an envelope but cannot expand it.

## Model routing stays host-owned

Hosts map `fast`, `standard`, and `deep` work to concrete models through the canonical
[model-tier reference](https://github.com/howarewoo/woostack/blob/main/skills/using-woostack/references/model-tiers.md).
OMP instead uses
[host-owned role routing](https://github.com/howarewoo/woostack/blob/main/skills/using-woostack/references/hosts/omp.md).
The host owns models, credentials, and fallbacks; woostack supplies the effective role or tier.
