---
title: Context management
description: "How woostack keeps context small, isolates heavy work, routes model tiers, and keeps agent output compact."
---

Context economy has three mechanisms. One of them, recall by scope, is the [Memory](/docs/concepts/memory)
store. The other two live here: shell scripts that compute and return a compact result, and
subagents that carry heavy work off the main thread. Each returns something small, so the bulk
never reaches the main context.

## Output stays compact

[using-woostack](/docs/skills/using-woostack) loads one shared output discipline for user replies
and internal handbacks: lead with the result, remove narration and repetition, and preserve exact
evidence, commands, paths, and errors. Requests for more detail override the terse default, while
security, destructive actions, root-cause analysis, and architecture keep the language needed to
remain unambiguous.

[woostack-review](/docs/skills/woostack-review) applies the same principle through its stricter
finding contract. Each inline comment uses a short title, one evidence-bearing description
sentence, one imperative fix sentence, and a compact severity-and-angle footer. A second sentence
or ordered fix steps remain available when the risk cannot be stated safely in the default shape.

## Scripts compute, agents read

woostack ships small shell scripts that do the filesystem, git, and GitHub work and print a compact
result. The agent reads the result, not the inputs that produced it.

- `build-index.sh` compresses every memory note down to one index line in `MEMORY.md`, so a skill
  reads the index instead of every note body.
- `recall.sh` runs the scope match and the one-hop expansion, then emits only the notes that
  matched.
- `status.sh` reads the specs, plans, and PR state and prints the feature board, so the agent never
  loads all those artifacts itself.
- `prefetch.sh` gathers a PR's diff, metadata, rules, memory, and wisdom once. For each touched
  right-side `SKILL.md`, it also snapshots and validates the whole tracked package. Review subagents
  read those artifacts rather than re-fetching GitHub or the mutable checkout; findings remain
  anchored only to changed lines in the authoritative diff.

This is what makes recall scale: on a repo with 500 notes, recall loads only the handful that match
the changed files, not the full corpus. Because the work happens in the shell, the results are
deterministic and the scripts are idempotent, so they are safe to run anytime, including in CI.

## Subagents isolate work

Some steps hand work to subagents. Each subagent runs in its own context window and returns only a
compact result, so the heavy reading and reasoning never land in the main thread.

- [woostack-execute](/docs/skills/woostack-execute) runs inline or with subagents. The smart
  default is subagents where the host can spawn them, inline otherwise. In subagent mode a fresh
  implementer writes each task, then a spec-compliance reviewer and a code-quality reviewer check
  the diff. Each is a separate agent that sees only what it needs.
- [woostack-review](/docs/skills/woostack-review) fans out one plain/default subagent per review
  angle in parallel. Those workers receive the worker contract, angle prompt, and prefetched
  artifacts directly — not the full review orchestrator skill — then two opposing validator passes
  keep only the findings both agree on.

Each subagent runs at a tier matched to the work, so cheap tasks do not burn an expensive model.
Hosts with explicit repository-model routing map these tiers to a concrete provider model through
[model-tiers.md](https://github.com/howarewoo/woostack/blob/main/skills/using-woostack/references/model-tiers.md).
omp uses a different, equally capable route: `deep -> slow`, `standard -> default`, and
`fast -> smol`, selected through **role-backed built-in workers** (`oracle`, `task`, and
`quick_task`). omp ignores `.woostack/config.json` model settings and owns the concrete model,
role configuration, credentials, and fallback. woostack passes only the effective tier through
that fixed worker map.

For hosts that consume the shared repository model configuration, the Anthropic defaults are:

| Tier | Use for | Anthropic model |
| --- | --- | --- |
| `fast` | rubric checks, mechanical one-or-two-file tasks, context summaries | `claude-opus-4-8` (effort `low`) |
| `standard` | reasoning workers, multi-file integration | `claude-opus-4-8` (effort `medium`) |
| `deep` | code-quality review, design and architecture judgment, skeptical validation | `claude-opus-4-8` (effort `xhigh`) |
