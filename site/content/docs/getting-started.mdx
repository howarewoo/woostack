<Callout type="info">
  The user's approved workflow contract defines scope. Git and GitHub own code, branches, pull
  requests, reviews, and merges. Available Linear capability records fix/build plans as project
  hierarchies but never authorizes repository work.
</Callout>

## 1. Install the skills

Install the collection with the package manager supported by your skill host:

```bash
pnpx skills add howarewoo/woostack
```

Confirm the host can discover `using-woostack` and the `/woostack-*` command skills. Keep repository
rules in the root `AGENTS.md`; do not copy workflow internals into project instructions.

## 2. Initialize local support

From the target repository, invoke:

```text
/woostack-init
```

Initialization creates or repairs non-secret `.woostack/config.json`, diagnostic report roots,
worktree support, and the three project-scoped OMP role workers. It preserves other project agents
and does not create a specification, plan, fix, issue, project, branch, or PR.

Read [Configuration](/docs/configuration) for optional policy. Artifact-free workflows need no
provider connection.

## 3. Choose the workflow

| Goal | Command |
| --- | --- |
| Create a genuinely greenfield codebase | `/woostack-bootstrap` |
| Build a multi-increment feature | `/woostack-build` |
| Fix a bug or regression | `/woostack-fix` |
| Make one bounded non-bug change/refactor | `/woostack-change` |
| Review a PR or local diff | `/woostack-review` |
| Address unresolved PR threads | `/woostack-address-comments` |
| Show current repository work state | `/woostack-status` |

The selected workflow's contract and approval gates authorize work. An issue or project is never a
prerequisite merely to run a command.

## 4. Optional: enable Linear plan persistence

Enable Linear when the repository should durably store feature specifications and fix/build plans.
Invoke:

```text
/woostack-init --linear
```

Configure only the host-exposed official Linear MCP endpoint:

```text
https://mcp.linear.app/mcp
```

Authentication stays in the host's MCP/OAuth secret store. Never place API keys, credentials,
tokens, or authorization headers in repository config, prompts, logs, or generated files.

The validated repository `linear` configuration triggers fix/build/plan capability preflight. When
the official MCP proves all required write/read-back operations, each plan is persisted as one
project, one parent plan issue, and one native child issue per increment. Missing capability leaves
automatic planning artifact-free. `woostack-change` never contacts Linear.

## 5. Optional: configure a Hermes + OMP engineer pair

The pair is one adapter for the [engineer-agent contract](/docs/concepts/engineer-agents):

- Hermes decides, performs independent review, comments, accepts, redispatches, and escalates.
- One isolated OMP profile implements one approved bounded task in one collision-safe worktree.
- Hermes never codes; OMP never reviews or accepts its own work.
- Git/GitHub evidence remains authoritative.

Create distinct Hermes and OMP profiles/sessions, role-owned credential/config roots, a stable
engineer name, and a canonical worktree contract. Confirm the installed OMP CLI invocation and use
an argument-safe PTY interface. Profile names alone are not isolation.

The pairing works without Linear. If a unit will read/write persisted plan artifacts, connect the
official MCP independently in each profile and keep their secret stores and sessions distinct.

Follow the exact setup and dispatch boundaries on the [Hermes](/docs/harnesses/hermes) and
[OMP](/docs/harnesses/omp) pages.

## 6. Optional: production-error response policy

`/woostack-init --respond` may validate non-secret observability defaults and available authenticated
provider capabilities. It never requests credentials or queries production during setup.

[woostack-respond](/docs/skills/woostack-respond) writes sanitized local diagnostic reports and
keeps raw provider evidence transient. Reports are advisory; a remediation route independently
hardens its fix/change/build contract and may run artifact-free.

## Recommended companions

Independent implementation skills such as framework, database, security, accessibility, or writing
review skills remain optional. They never replace the selected woostack workflow's scope, approval,
verification, or review boundaries.
