This page lists the non-secret repository settings read by woostack. Artifact storage has its own
[reference section](/docs/configuration/artifacts) because local storage and remote mirroring have
different fields and guarantees.

Configuration never contains credentials, grants permission to perform repository work, or approves
artifact content.

## Configuration files

| File | Tracking | Scope |
| --- | --- | --- |
| `.woostack/config.json` | Tracked | Shared repository policy. `woostack-init` creates this file. |
| `.woostack/config.local.json` | Gitignored by `*.local.*` | Optional primary-checkout overrides. Linked worktrees inherit it through the Git common directory. |

If both files are absent, each consumer keeps its built-in defaults. A local override without
the tracked base file stops configuration loading with an error.

## Merge and validation rules

| Rule | Behavior |
| --- | --- |
| Object merge | Objects merge recursively. |
| Scalar, array, or `null` override | The local value replaces the base value. Arrays do not concatenate. `null` does not delete a key. |
| Invalid input | Empty, malformed, non-object, unreadable, symlinked, non-regular, orphaned, or credential-like configuration fails closed with the offending path. |
| Secrets | Provider authentication stays in the host secret store. Both configuration files contain non-secret policy only. |
| Doctor | `woostack-doctor` validates effective runtime configuration. Template presence checks and repairs apply only to `.woostack/config.json`. |
| OMP models | OMP ignores `models`. Its profile and fixed role workers own model selection and recovery. |

This partial example shows how the two files merge. It is not a complete Linear configuration;
the [Linear page](/docs/configuration/artifacts/linear) lists the required fields.

Given this base configuration:

```json
{
  "artifacts": {
    "provider": "linear",
    "linear": {
      "repository": "https://github.com/acme/widgets",
      "workspace": "acme",
      "team": "ENG"
    }
  }
}
```

and this local override:

```json
{
  "artifacts": {
    "linear": {
      "team": "LOCAL-ENG"
    }
  }
}
```

keeps `repository` and `workspace`, and sets `team` to `LOCAL-ENG`.

## Top-level settings

This page covers eight top-level settings. The init template writes `artifacts`, `models`,
`review`, and `status`. Consumers supply defaults for omitted settings, subject to the requirements below.

| Setting | Read by | Purpose |
| --- | --- | --- |
| [`artifacts`](/docs/configuration/artifacts) | Init, Build, Fix, Plan, Execute, and selected artifact-aware workflows | Selects local storage or optional GitHub, Linear, or Plane mirroring. |
| `review` | [woostack-review](/docs/skills/woostack-review) | Review angles, finding visibility, diff filters, skip rules, tier forcing, chunking, and metrics. |
| `models` | Review, Audit, and host subagent drivers | Shared fast, standard, and deep model leaves for hosts that consume repository model policy. OMP ignores this setting. |
| `audit` | [woostack-audit](/docs/skills/woostack-audit) | Standing-code audit angles, filtering, chunking, severity floor, and report directory. |
| `review_sweep` | [woostack-sweep](/docs/skills/woostack-sweep) | Maximum review rounds for one stack sweep. |
| `commit` | [woostack-commit](/docs/skills/woostack-commit) | Command to run before staging. |
| `status` | [woostack-status](/docs/skills/woostack-status) | Age threshold for stale active rows. |
| `base_branch` | Init and worktree workflows | Trunk branch used for worktrees and pull requests. |

## A complete example

This example combines optional settings; it is not the init template. Use model IDs supported by
your host and replace `commit.command` with commands your repository actually provides.
JSON has no comments, so the tables below explain each setting.

```json
{
  "artifacts": {
    "provider": "local"
  },
  "review": {
    "severity_floor": "high",
    "nits": true,
    "angles": {
      "force": ["tests"],
      "skip": ["seo"]
    },
    "ignore": ["**/*.generated.ts", "pnpm-lock.yaml"],
    "project_rules": ["docs/engineering/rules.md"],
    "authors_skip": ["dependabot[bot]", "renovate[bot]"],
    "force_tier": "",
    "chunking": { "max_loc": 4000 },
    "defer_markers": true,
    "metrics": false
  },
  "models": {
    "fast": { "model": "google/gemini-3-5-flash", "effort": "low" },
    "standard": { "model": "openai/gpt-5.5", "effort": "medium" },
    "deep": { "model": "anthropic/claude-opus-4-8", "effort": "xhigh" }
  },
  "audit": {
    "severity_floor": "high",
    "angles": {
      "force": [],
      "skip": ["deps"]
    },
    "ignore": ["**/*.generated.ts"],
    "chunking": { "max_loc": 4000 },
    "report_dir": ".woostack/audits"
  },
  "review_sweep": { "max_rounds": 3 },
  "commit": { "command": "pnpm format && pnpm test" },
  "status": { "staleDays": 14 },
  "base_branch": "main"
}
```

## Review engine

All review keys nest under `review`. [woostack-review](/docs/skills/woostack-review) validates the
types when it runs; an unknown key inside `review` is a hard error.

Keep a `review` object in an existing configuration file, even when you want defaults (`"review": {}`).
Without it, the current loader treats the entire file as legacy review settings and rejects sibling
keys such as `artifacts`, `commit`, and `review_sweep`. The init template already includes `review`.

### Finding severity and nits

A finding at or above the severity floor is a normal (blocking-eligible) finding. A finding below
the floor is surfaced as a non-blocking nit, or dropped entirely when nits are off. A below-floor
finding explicitly marked blocking always surfaces regardless of the floor.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `review.severity_floor` | string | `"high"` | Threshold: `low`, `medium`, or `high` (case-insensitive). |
| `review.nits` | boolean | `true` | `true` posts below-floor findings as `Nit:` comments; `false` drops them. |

### Angle selection

The review engine selects angles, or specialist checks, from the diff and verified context.
A small, low-risk local review may use one reviewer covering the whole diff. Explicit force/skip
settings keep separate specialists; `force` wins a tie and `bugs` cannot be skipped. CI and Audit
keep separate specialist reviewers.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `review.angles.force` | array of string | `[]` | Angles always enabled. |
| `review.angles.skip` | array of string | `[]` | Angles excluded from specialist selection (except `bugs`). |

See the [review angle reference](/docs/concepts/review-angles) for each check. The detector script
owns the exact selection rules; each worker prompt declares its model tier.

### Filtering the diff

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `review.ignore` | array of string | `[]` | File patterns using Python's `fnmatch` syntax; matching files are excluded from angle detection and the diff before analysis. |
| `review.project_rules` | array of string | `[]` | Shell glob patterns for extra rule files, relative to the repo root. These join the automatically collected rules in `rules.md` and trigger `conventions`. |

### Skipping PRs automatically

By default, review skips PRs from `dependabot[bot]`, `renovate[bot]`, and `github-actions[bot]`,
as well as PR titles matching the release-rollup pattern `^(staging\|release\|chore\(release\))`.
It posts a skip comment instead of running the review. To disable either rule, use an empty
`authors_skip` array or an empty pattern string.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `review.authors_skip` | array of string | three bots (above) | PR author logins that short-circuit the review. `[]` opts out. |
| `review.release_rollup_pattern` | string | release regex (above) | Python regex matched against the PR title. `""` opts out. |

### Model selection

Each review subagent runs at a tier (`fast`, `standard`, or `deep`). On hosts that consume
repository model configuration, the top-level `models` namespace maps that tier to a concrete
model and optional effort. The namespace sits at the root, not under `review`, so review, audit,
and local subagent drivers can share it.

omp is the host-owned exception. It ignores the entire `models` namespace and maps the effective
tier to its fixed init-managed role worker instead. Changing a flat or provider-specific model leaf
never changes an omp dispatch.

| Host | Repository model config | Flat fallback | Dispatch behavior |
| --- | --- | --- | --- |
| Claude Code | `models.anthropic.fast`, `.standard`, or `.deep` | matching flat leaf | Passes the resolved Anthropic model and effort to each Task call. The single-session CI action can pass the model, but not effort. |
| Codex | `models.openai.fast`, `.standard`, or `.deep` | matching flat leaf | Passes the resolved OpenAI model and reasoning effort when the host supports per-call overrides. A single-model session resolves once for the whole run. |
| Gemini | `models.google.fast`, `.standard`, or `.deep` | matching flat leaf | Uses the Google model for the resolved tier. |
| OpenRouter | `models.openrouter.fast`, `.standard`, or `.deep` | matching flat leaf | Uses the OpenRouter model and reasoning effort for the resolved tier. |
| omp (Oh My Pi) | ignored | ignored | Selects the fixed role-backed worker; omp owns its model and fallback. |

For hosts that consume this namespace, a provider-specific leaf takes precedence over the
matching flat leaf. The same config file can therefore supply provider-neutral defaults and
provider-specific overrides:

```json
{
  "models": {
    "fast": { "model": "google/gemini-3-5-flash", "effort": "low" },
    "standard": { "model": "openai-codex/gpt-5.6-sol", "effort": "medium" },
    "deep": { "model": "anthropic/claude-opus-4-8", "effort": "xhigh" },
    "anthropic": {
      "fast": { "model": "claude-opus-4-8", "effort": "low" },
      "standard": { "model": "claude-opus-4-8", "effort": "medium" },
      "deep": { "model": "claude-opus-4-8", "effort": "xhigh" }
    },
    "openai": {
      "fast": { "model": "gpt-5.5", "effort": "low" },
      "standard": { "model": "gpt-5.5", "effort": "medium" },
      "deep": { "model": "gpt-5.5", "effort": "high" }
    }
  }
}
```

In this example, Claude Code selects the Anthropic branch and Codex selects the OpenAI branch.
Another repository-model host can use the flat leaves. omp ignores every entry in the block.
How each non-omp host consumes the schema, including spawn primitives, per-call routing knobs,
and fallback, lives in its canonical host reference under
`skills/using-woostack/references/hosts/`.

Each tier leaf supports all three shared forms:

- a model-slug string;
- an object `{ "model": "<slug>", "effort": "<level>" }`; or
- a non-empty ordered array of either form, used as a fallback preference list.

Supported effort levels are `minimal`, `low`, `medium`, `high`, and `xhigh`.
`review.force_tier` pins review angle workers to one tier, like running the review with `--fast`
or `--deep`. The evidence adjudicator, which checks the workers' findings, stays at `standard`.

In an array, entry 0 is the primary model. Later entries list fallback models in preference order;
the host decides whether and how to use them. A review host with per-call model overrides can
retry a rate-limited worker with a later entry. Other consumers follow their host reference.
omp ignores the array. An empty array is a configuration error.

```json
{
  "models": {
    "deep": [
      { "model": "openai-codex/gpt-5.6-sol", "effort": "xhigh" },
      { "model": "openai-codex/gpt-5.6-sol", "effort": "high" },
      "google/gemini-3-5-flash"
    ]
  }
}
```

The [complete example](#a-complete-example) uses flat leaves to assign non-omp hosts a model for
each tier.

A `review.models` block is a configuration error; put `models` at the top level.
`woostack-doctor` warns if it finds `review.models`.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `models.fast`, `models.standard`, `models.deep` | string, `{model, effort}`, or array of those (fallback list) | provider table | Provider-agnostic model for the three shared tiers on repository-model hosts. |
| `models.anthropic.*`, `models.openai.*`, `models.google.*`, `models.openrouter.*` | string, `{model, effort}`, or array of those (fallback list) | provider table | Per-provider override, with one `fast`, `standard`, or `deep` leaf. |
| `review.force_tier` | string | absent | Pin angle workers to `fast` or `deep`; the adjudicator stays at `standard`. Empty string leaves prompt tiers unchanged. |

The default model per provider and tier:

| Provider | `fast` | `standard` | `deep` |
| --- | --- | --- | --- |
| anthropic | `claude-opus-4-8` (effort `low`) | `claude-opus-4-8` (effort `medium`) | `claude-opus-4-8` (effort `xhigh`) |
| openai | `gpt-5.5` | `gpt-5.5` | `gpt-5.5` |
| google | `gemini-3-5-flash` | `gemini-3-5-flash` | `gemini-3-5-flash` |
| openrouter | `openrouter/deepseek/deepseek-v4-flash` | `openrouter/deepseek/deepseek-v4-pro` | `openrouter/deepseek/deepseek-v4-pro` |

Anthropic routes every tier to `claude-opus-4-8`, so the tier is carried by reasoning `effort`
(`low`/`medium`/`xhigh`) rather than by the model. Effort applies on per-call hosts (Claude Code);
the CI single-session `claude-code-action` step passes only the model.

For Review, a PR comment's `--fast` or `--deep` override takes priority over the action's
`force_tier` input, which takes priority over `review.force_tier`. Without a forced tier, local
workers use their prompt tiers. On hosts that read repository model policy, model resolution
then follows the action's explicit `model` input, the provider-specific leaf, the flat leaf,
and the provider default. Single-model CI sessions resolve one model for the whole run.
On omp, the effective tier selects a fixed worker; the host owns its model.

### Chunking, adjudication, and metrics

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `review.chunking.max_loc` | integer ≥ 0 | `4000` | Changed-line threshold; a larger diff is split into chunks and each angle fans out across them. `0` disables chunking. |
| `review.defer_markers` | boolean | `true` | `true` honors inline `woostack-defer(<ref>)` markers, demoting a matching finding to a non-blocking nit. `security` findings are never deferred. |
| `review.metrics` | boolean | `false` | `true` writes a per-angle signal/noise breakdown, folds a rolling non-authoritative local `.woostack/metrics.json`, and prints advisory `review.angles.skip` suggestions when an optional angle has at least 20 local runs with zero blockers and either zero kept findings or only nit findings. |
| `review.fix_commands` | array of string | `[]` | Reserved for a future loop mode; parsed but not yet consumed. |

## Audit engine

Audit settings nest under `audit`. [woostack-audit](/docs/skills/woostack-audit) rejects unknown
keys in this object. By default it forces `simplify` and `production-readiness` and skips
`architecture`. `--simplify` removes the default production-readiness check; `--prod-only`
keeps simplification. Configured force and skip lists modify the selected specialists, with
force taking priority. See the skill for its required safety checks.

The skill requires both bug and security checks. The current detector always includes `bugs`,
but selects `security` conditionally and allows it to be skipped. Check the reported angle list;
the configuration scripts alone do not guarantee the skill's required security coverage.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `audit.angles.force` | array of string | `[]` | Additional review angles to run. |
| `audit.angles.skip` | array of string | `[]` | Additional angles to skip. `simplify` cannot be skipped. |
| `audit.severity_floor` | string | `"high"` | Finding threshold: `low`, `medium`, or `high`. |
| `audit.ignore` | array of string | `[]` | Globs excluded from the synthetic audit diff. |
| `audit.chunking.max_loc` | integer ≥ 0 | `4000` | Changed-line threshold for splitting the synthetic diff into chunks. |
| `audit.report_dir` | string | `".woostack/audits"` | Repository-relative directory for audit reports. |

Root model tiers also drive [woostack-audit](/docs/skills/woostack-audit) on hosts that consume
repository model configuration. Put overrides in the root `models` namespace using flat leaves
(`models.fast`, `models.standard`, `models.deep`) or provider-specific leaves. A nested
`audit.models` block is a hard error.

## Sweep rounds

[woostack-sweep](/docs/skills/woostack-sweep) works through a stack of PRs from bottom to top.
It addresses existing threads before reviewing each PR, then addresses new findings.
Git + `gh` is the default; Graphite is optional for an explicitly selected or verified
already-managed stack. Native Sweep reconciles descendants by merging each verified parent tip
into its child branch and pushing normally, without rebasing or force-pushing. This is a local
branch operation, not a GitHub PR merge; agents never merge PRs or advance them toward merge.
The [source-control contract](https://github.com/howarewoo/woostack/blob/main/skills/woostack-commit/references/graphite.md)
owns backend selection and mechanics. Backend failures stop rather than switch modes.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `review_sweep.max_rounds` | integer > 0 | `3` | Maximum review-and-address rounds per PR before Sweep stops as blocked. A non-positive or non-integer value warns and falls back to `3`. |

The [Sweep workflow](/docs/skills/woostack-sweep) defines when a changed PR needs another review
and what evidence is required before moving to the next PR. Resolving a thread alone does not
clear a recorded blocker.

## Commit hook

[woostack-commit](/docs/skills/woostack-commit) can run a command before it stages anything: a
formatter, linter, or test runner.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `commit.command` | string | absent (no command) | Nonempty command run exactly once before staging. Failure blocks the commit. If it changes files, prior verification is invalidated and Commit returns to the calling workflow. |

## Status board

[woostack-status](/docs/skills/woostack-status) flags an active repository row that has remained
unchanged past the configured threshold.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `status.staleDays` | integer | `14` | Days of inactivity before an active repository row is flagged stale. |

## Base branch

`base_branch` is a top-level string (not nested) naming the trunk branch that PRs target and that
worktrees are cut from.

| Key | Type | Default | Meaning |
| --- | --- | --- | --- |
| `base_branch` | string | auto-detected | Trunk branch name. `WOOSTACK_BASE_BRANCH` takes priority, followed by this setting, the remote's default branch, then `main`. |

## Defaults and doctor

<Callout type="info">
  Init scaffolds `artifacts`, `models`, `review`, and `status`, and automatically adds validated
  Linear defaults when safe authenticated discovery succeeds. When `artifacts.provider: "github"`,
  Init discovers GitHub defaults via `gh`. Missing connectivity never blocks
  local initialization. Build and project-backed Fix use
  [local run authority](/docs/configuration/artifacts/local) with optional configured provider
  mirrors. Bounded Fix and goal-only Change remain provider-free. Change with explicit exact
  canonical GitHub issue input performs the required read of that issue through host-authenticated
  `gh`; no artifact-provider configuration, Project, mirror, or persisted plan is required.
  [woostack-doctor](/docs/skills/woostack-doctor) validates effective runtime policy; explicit live checks
  prove optional artifact connectivity.
</Callout>

## Migration notes

- `AUDIT_CONFIG_FILE` is removed: [woostack-audit](/docs/skills/woostack-audit) reads effective configuration through the canonical resolver.
- Review empty-config fallback is removed: an empty `.woostack/config.json` fails closed as malformed instead of falling back to default values.
