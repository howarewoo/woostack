Select GitHub artifact mirroring with `artifacts.provider: "github"`. For Build and project-backed
Fix, the [local run](/docs/configuration/artifacts/local) remains the source of truth.

## Configuration

Replace the example owner and status options with verified values from your GitHub account or
organization. The five status options must exist on the selected single-select field and have
distinct names.

```json
{
  "artifacts": {
    "provider": "github",
    "github": {
      "owner": "acme",
      "ownerType": "organization",
      "statusField": "Status",
      "visibility": "private",
      "projectStatuses": {
        "planned": "Todo",
        "executing": "In Progress",
        "inReview": "In Review",
        "done": "Done",
        "blocked": "Blocked"
      }
    }
  }
}
```

| Field | Type | Constraint |
| --- | --- | --- |
| `artifacts.github.owner` | string | Required nonempty GitHub organization or user login. |
| `artifacts.github.ownerType` | string | Optional `"organization"` or `"user"`. Resolved via discovery when omitted. |
| `artifacts.github.statusField` | string | Optional exact case-sensitive single-select field name. Defaults to `"Status"`. |
| `artifacts.github.visibility` | string | Optional `"private"` or `"public"`. Defaults to `"private"`; applies only to newly created Projects. |
| `artifacts.github.projectStatuses` | object | Required mapping of exactly five keys (`planned`, `executing`, `inReview`, `done`, `blocked`) to nonempty, distinct option names on the configured status field. |

Credentials belong in the host's authenticated `gh` environment, never in repository configuration.
Projects v2 and native dependencies use `gh api graphql`; repository issue operations use GitHub issue
APIs through `gh`. Custom HTTP/GraphQL clients, credential reads, and token forwarding are forbidden.

### Transport capabilities and boundaries

The GitHub provider requires host-authenticated `gh` with these verified capabilities:
- Projects: `projectRead`, `projectWrite`, and `projectDelete` (deletion is used for smoke testing).
- Issues: `issueRead`, `issueWrite`, `issueClose`, and `issueDelete` (deletion is used for smoke testing).
- Dependencies: `dependencyRead` and `dependencyWrite`.
- Status field: `statusFieldRead` and `statusFieldWrite`.
- Reads: complete `pagination` and `independentReadBack`.

Missing capabilities, unauthorized scopes, another run's markers, unexpected changes, or partial
responses stop the provider operation.

## Identities, hierarchy, and graph

Accepted canonical URL forms are:
- Projects: `https://github.com/orgs/<owner>/projects/<N>` (organizations) or `https://github.com/users/<owner>/projects/<N>` (users).
- Issues: `https://github.com/<owner>/<repo>/issues/<N>`.

Use these URLs to select resources and associate them with a PR. GitHub's internal GraphQL node
IDs and Project item IDs are kept separately for API changes.

Build and project-backed Fix resolve an exact supplied Project URL or create one `[Build]/[Fix] <goal>`
Project under the configured owner. The complete specification is written inside `ProjectV2.readme`
between markers `<!-- woostack-spec-start -->` and `<!-- woostack-spec-end -->`, preserving unrelated
README bytes. `shortDescription` contains a concise goal summary.

Each increment is a normal repository issue with no parent (`parent = null`), added directly to the
Project. Woostack does not create an extra parent plan issue or draft item. Before creating resources,
it allocates recovery markers (`<!-- woostack-project-mutation:<UUID> -->` and
`<!-- woostack-issue-mutation:<UUID> -->`) so later reads can detect an uncertain creation result
without creating a duplicate.

GitHub plans use explicit prerequisite graphs. Independent roots, forks, chains, and joins are
valid; only genuine prerequisites become native `blocked-by` edges. Stable ordinals control display
and tie-breaking, not dependencies or Git ancestry. Existing chain edges are preserved unless the
approved plan explicitly changes them.

Each root records its approved integration parent. Dependents record their prerequisites and a
parent-selection policy; a concrete Git parent and SHA require verified delivered-branch evidence.
A join without one parent containing all required changes remains valid but cannot run until an
explicit parent/integration decision is made. Planning never creates an automatic integration branch.

Synchronization validates the complete graph before mutations and independently reads back every
issue, membership, and exact edge. Missing or foreign endpoints, ambiguous identities, cycles, and
incomplete pagination block; they do not expand Project scope.

Current Execute remains sequential. GitHub DAG planning and mirroring do not make branching graphs
executable through `--project`, `--issue`, or `--run`. Those graphs remain retained for the intended
Orchestrate consumer; Linear, Plane, and local-only planning keep their existing sequence.

## Lifecycle and closure (retired Execute reference)

> **Retired.** Execute no longer performs GitHub Project/issue lifecycle transitions, project/run
> controller reads, closure, or `--project`/`--run`/`--recheck` scope. It accepts one complete bounded
> task and an optional exact canonical GitHub issue URL; see
> [Execute retired inputs](/docs/skills/woostack-execute#retired-inputs).

Standalone provider-backed Plan remains the only workflow that closes an exact admitted Project.
Build/Fix handoff, abandonment, blockers, and completion leave any mirrored Project unchanged.

## Workflow matrix

| Skill | GitHub provider behavior |
| --- | --- |
| [woostack-build](/docs/skills/woostack-build) | Resolves an exact supplied Project or creates one `[Build] <goal>` Project; writes specification to managed README; creates parentless issues with direct Project membership; and wires explicit prerequisite edges. |
| [woostack-fix](/docs/skills/woostack-fix) | Bounded Fix is provider-free. Project-backed Fix proves root cause before provider access, preserves an exact source `--issue` as context with a direct Project link, and creates/reconciles a separate increment DAG. |
| [woostack-plan](/docs/skills/woostack-plan) | Standalone Plan requires an exact existing canonical Project URL (`orgs/<owner>/projects/<N>` or `users/<owner>/projects/<N>`) and synchronizes the direct issue graph; delegated Plan is provider-free. |
| [woostack-execute](/docs/skills/woostack-execute) | Accepts one complete bounded task plus an optional exact GitHub issue URL; retired `--project`, `--run`, and `--recheck` are rejected. |
| [woostack-init](/docs/skills/woostack-init) | Discovers owner, ownerType, canonical repository, and status options through read-only `gh` calls only when `artifacts.provider: "github"`. Never selects persistence or probes writes. |
| [woostack-status](/docs/skills/woostack-status) | Adds read-only context only after verifying repository/PR identity. Provider records cannot create rows or override repository evidence. |
| [woostack-bootstrap](/docs/skills/woostack-bootstrap) | Optional persistence only after explicit design approval and approval to write to the verified filesystem target. |
| [woostack-init](/docs/skills/woostack-init) | Discovers owner, ownerType, canonical repository, and status options through read-only `gh` calls only when `artifacts.provider: "github"`. Never selects persistence or probes writes. |
| [woostack-doctor](/docs/skills/woostack-doctor) | Checks config types locally. Explicit live checks verify authenticated identity and required capabilities, including deletion capability needed for smoke testing, without storing secrets. |
| [woostack-change](/docs/skills/woostack-change) | Goal-only Change is provider-free. An explicit exact canonical GitHub issue input performs the required read of that issue through host-authenticated `gh`; it requires no artifact-provider configuration, Project, or mirror, and performs no issue lifecycle writes. |
