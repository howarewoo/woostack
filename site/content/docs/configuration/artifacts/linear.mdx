Linear is a surviving explicit provider for workflows that select it. Prepare and Plan do not mirror
packets to Linear; Plan publishes directly to GitHub. Historical records remain readable and are not
migrated.

## Configuration

All fields shown below are required when Linear is selected. Replace the example names with
verified values from your workspace; status names are not universal defaults.

```json
{
  "artifacts": {
    "provider": "linear",
    "linear": {
      "repository": "https://github.com/acme/widgets",
      "workspace": "acme",
      "team": "ENG",
      "projectLabels": ["feature"],
      "projectStatuses": {
        "backlog": "Backlog",
        "planned": "Planned",
        "started": "Started",
        "completed": "Completed",
        "canceled": "Canceled"
      },
      "issueStates": {
        "planned": "Backlog",
        "executing": "In Progress",
        "inReview": "In Progress",
        "done": "Done",
        "blocked": "In Progress"
      }
    }
  }
}
```

| Field | Type | Constraint |
| --- | --- | --- |
| `artifacts.linear.repository` | string | Canonical `https://github.com/<owner>/<repo>` URL. The configuration resolver requires this URL form; a bare `owner/repo` is not accepted. |
| `artifacts.linear.workspace` | string | Exact Linear workspace. |
| `artifacts.linear.team` | string | Exact team identifier or name. |
| `artifacts.linear.projectLabels` | string array | Required when Linear is selected. May be empty. Labels resolve by exact native identity or exact case-sensitive name. |
| `artifacts.linear.projectStatuses.*` | string | Required keys: `backlog`, `planned`, `started`, `completed`, `canceled`. Each value is a native status ID or exact case-sensitive name. Woostack checks the status category before a transition. |
| `artifacts.linear.issueStates.*` | string | Required keys: `planned`, `executing`, `inReview`, `done`, `blocked`. Each value is a native state ID or exact case-sensitive name. Woostack checks the state category before a transition. |

Credentials belong in the host's authenticated official Linear MCP or OAuth secret store, never in
repository configuration.

## Identities and hierarchy

Use readable issue identifiers such as `ENG-42` to select and refer to issues. Linear's internal
UUIDs are kept separately for API changes.

Historical provider-backed records may refer to a selected Linear project. Bounded Change, Prepare,
and Plan do not contact Linear; Plan's direct GitHub publisher owns parent/child/dependency
publication.

## Lifecycle behavior (retained-record reference)

> **Boundary.** Execute accepts one complete bounded task and no Linear/Plane issue scope. Retained
> provider status fields and historical records do not grant lifecycle authority to a new command. See
> [Execute retired inputs](/docs/skills/woostack-execute#retired-inputs).

`woostack-init` may discover missing non-secret Linear defaults through authenticated read-only MCP
calls. Discovery does not select Linear as the provider and does not authorize later access.

Bootstrap may mirror an approved design after the user approves writing to the verified filesystem
target and explicitly selects provider persistence. Commit verifies an exact `--issue <id>`, adds
the required merge-closing PR reference, and may write a requested delivery note with an independent
read to confirm it was saved.

See the [Linear provider contract](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/artifact-providers/linear.md)
for label preservation, duplicate-safe recovery, and lifecycle checks.
