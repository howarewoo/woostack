Development records are specifications, plans, and evidence retained for history. Plan publishes
issues directly when the request asks for it and creates no run or second remote record. A readable
tracker index with independently readable executable issues can be a declared handoff when native
relationships are absent, partial, or unavailable; that is not a verified native graph. Existing
`.woostack/tmp/runs/<run-id>/` files remain readable user data and are never migrated or mutated.
Execute accepts one complete bounded task and does not consume a Project or retained run as
executable scope.

## Guarantees

Configuration is non-secret policy. The optional top-level `github` object is the only active remote
configuration surface; its allowed fields are `owner`, `ownerType`, `statusField`, and
`projectStatuses`. Missing GitHub configuration is valid, and issue or exact-issue workflows do not
require Project or Status settings.

A requested Plan publication uses the repository and destination the request resolves. No Project
destination is guessed, and a GitHub failure is reported with its confirmed identity boundary. The
[GitHub page](/docs/configuration/artifacts/github) owns capability preflight, read-back, and
lifecycle; the [local page](/docs/configuration/artifacts/local) owns retained-record preservation
and recovery. Both trace to the
[artifact contract](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/artifact-backends.md#direct-publication-and-recovery)
and the [GitHub profile](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/artifact-providers/github.md#configuration-and-scope).
