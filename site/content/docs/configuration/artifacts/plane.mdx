Plane is a surviving explicit provider for workflows that select it. Prepare and Plan do not mirror
packets to Plane; Plan publishes directly to GitHub. Historical records remain readable and are not
migrated.

## Configuration

All fields shown below are required when Plane is selected. Replace the example project UUID,
labels, and state names with verified values from your instance.

```json
{
  "artifacts": {
    "provider": "plane",
    "plane": {
      "baseUrl": "https://api.plane.so",
      "workspace": "acme",
      "repository": "https://github.com/acme/widgets",
      "project": "33333333-3333-4333-8333-333333333330",
      "projectLabels": ["Core"],
      "issueStates": {
        "planned": "Backlog",
        "executing": "In Progress",
        "inReview": "In Progress",
        "done": "Done",
        "blocked": "In Progress"
      }
    }
  }
}
```

| Field | Type | Constraint |
| --- | --- | --- |
| `artifacts.plane.baseUrl` | string | Canonical Plane Cloud or self-hosted API base URL. |
| `artifacts.plane.workspace` | string | Exact workspace. |
| `artifacts.plane.repository` | string | Canonical `https://github.com/<owner>/<repo>` URL. The configuration resolver requires this URL form; a bare `owner/repo` is not accepted. |
| `artifacts.plane.project` | string | Exact Plane project URL or native UUID. All specification and increment work items attach to this project. |
| `artifacts.plane.projectLabels` | nonempty string array | Required when Plane is selected. Labels resolve by exact native UUID or exact case-sensitive name. |
| `artifacts.plane.issueStates.*` | string | Required keys: `planned`, `executing`, `inReview`, `done`, `blocked`. Each value is a native state UUID or exact case-sensitive name. Woostack checks the state group before a transition. |

Credentials belong in the host's authenticated official Plane MCP or OAuth secret store, never in
repository configuration. Plane supports Cloud and self-hosted instances. Its configuration is
manual; Init does not discover Plane defaults.

## Identities and hierarchy

Woostack resolves the configured project and checks its instance, workspace, and repository
association for an explicitly selected surviving provider workflow. Historical specification and
increment items remain associated with that project. Prepare and Plan do not contact Plane;
Plan's direct GitHub publisher owns parent/child/dependency publication. Readable work-item references,
internal UUIDs, and external recovery IDs remain separate. Woostack never guesses or creates the
project.

## Lifecycle behavior (retained-record reference)

> **Boundary.** Execute no longer accepts Plane work-item scope or performs provider state
> transitions. Its only optional provider input is an exact canonical GitHub issue URL; retained Plane
> schema and historical records do not grant lifecycle authority to a new command. See
> [Execute retired inputs](/docs/skills/woostack-execute#retired-inputs).

The configured Plane project remains repository association context; its status is never changed by
woostack. Handoff, abandonment, blockers, and completion leave the project unchanged.

Bootstrap may mirror an approved design after the user approves writing to the verified filesystem
target and explicitly selects provider persistence. Commit verifies an exact `--issue <id>`, adds
the required merge-closing PR reference, and may write a requested delivery note with an independent
read to confirm it was saved.

See the [Plane provider contract](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/artifact-providers/plane.md)
for label preservation, recovery IDs, state groups, and retained-run compatibility checks.
