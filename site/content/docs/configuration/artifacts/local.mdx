title: Local
description: Reference for retained local planning records, preservation, and recovery boundaries.

`artifacts.provider` omitted or set to `"local"` is the default configuration. It does not create a
new planning run. Prepare and Plan use complete plain packets and direct GitHub issue publication;
Ideate and Harden are read-only public phases.

## Retained storage layout

Existing records from retired planning wrappers may contain:

```text
.woostack/tmp/runs/<run-id>/
├── .lock
├── manifest.json
├── project-spec.md
└── execution-plan.md
```

The [run-store contract](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/artifact-backends.md#owner-only-local-run-store)
defines historical naming, permissions, compare-and-swap revisions, and collision handling. Do not
create, rewrite, migrate, or delete a retained record as part of Prepare or Plan.

| Entry | Historical purpose |
| --- | --- |
| `.lock` | Prevents concurrent legacy run-store operations from overwriting each other. |
| `manifest.json` | Retained resume state, stable task mappings, mirror results, and revisions. |
| `project-spec.md` | Retained approved specification and, where applicable, proved diagnosis. |
| `execution-plan.md` | Retained increments, contracts, and dependencies. |

Historical records use owner-only permissions and atomic compare-and-swap writes when their owning
legacy operation is explicitly selected. Their presence is evidence, not permission or authority.

## Authority and provider behavior

Git and GitHub own source, branches, commits, pull requests, reviews, and merge state. A retained
artifact records decisions and evidence; it does not authorize publication, implementation,
assignment, ownership, acceptance, or merge.

With local or omitted configuration:

- Prepare, Ideate, Harden, and Plan make no provider-mirror calls;
- Plan still reads and publishes the exact GitHub scope selected by `--parent-issue` or `--project`;
  parent mode needs no provider selector, local run, Project settings, or mirror;
- goal-only [Change](/docs/skills/woostack-change) makes no artifact-provider calls; and
- issue-backed Change reads only its explicitly selected exact canonical GitHub issue through
  host-authenticated `gh`.

Automatic read-only discovery during `woostack-init` is setup only. It never selects remote storage or
authorizes later provider access.

## Retention and recovery

Completed and explicitly abandoned records remain unchanged. To continue from a retained record,
supply its exact identity and complete content to Prepare, Harden, or Plan after fresh repository and
evidence validation. An issue or run ID alone is insufficient; no automatic conversion or publication
is performed.

The retired `/woostack-execute --run <exact-run-id> [--recheck]` input is rejected. Select one
complete bounded task and supply it as `/woostack-execute <bounded input>` (see
[Execute retired inputs](/docs/skills/woostack-execute#retired-inputs)). Titles, recent history,
branch names, and search ranking are not selectors. Legacy tracked records remain unchanged unless
the user explicitly invokes the guarded
[woostack-init migration route](/docs/skills/woostack-init#optional-guarded-legacy-migration).
