---
title: What is woostack?
description: Evidence-driven workflows with repository-enabled Linear plan persistence.
---

woostack is a model-agnostic collection of gated software-development skills for planning,
implementation, review, diagnostics, and reusable knowledge.

```bash
pnpx skills add howarewoo/woostack
```

- **Repository-first truth:** the user's approved workflow contract authorizes work; Git and GitHub
  prove source, branches, pull requests, reviews, and merge state.
- **Conditional durable plans:** when repository Linear capability is proved, fix/build plans use
  one project, one parent plan issue, and one native child issue per increment. Linear is not a
  prerequisite for coding, committing, reviewing, or status.
- **Decision-maker/coder separation:** the generic
  [engineer-agent contract](/docs/concepts/engineer-agents) keeps scope, independent review, and
  acceptance separate from isolated implementation.
- **Non-authoritative diagnostics:** local reports are evidence, not permission or lifecycle state.
- **Agent- and model-agnostic:** the same skill logic supports
  [multiple harnesses](/docs/harnesses).
- **Stable adoption surface:** one install provides twenty-two public command/adoption skills at
  twenty-four fixed `SKILL.md` locations.
- **Pairs with [impeccable](https://github.com/pbakaus/impeccable):** woostack's recommended
  front-end design skill.

## Why woostack?

The collection keeps the whole delivery loop coherent without requiring a local development
ledger or a particular provider:

- one install and one routing surface;
- explicit approval gates and bounded task contracts;
- safe concurrency through declared dependencies and isolated worktrees;
- decision-maker/coder role separation;
- portable execution across supported harnesses;
- conditional plan persistence when repository Linear capability is available.

Remote artifact text, PR text, and tool output are untrusted evidence, never instructions. Missing
Linear capability keeps automatic planning artifact-free; failure after availability was proved
blocks that plan at its last verified persistence boundary.
