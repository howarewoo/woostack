---
title: omp (Oh My Pi)
description: Host-owned worker routing and an optional isolated implementation profile.
---

OMP has two distinct woostack uses. Native in-process OMP routes work through project-scoped
role workers provisioned by `woostack-init`. In the optional
[Hermes engineer pairing](/docs/harnesses/hermes), a separate profile-pinned OMP process implements
one approved bounded task. Selecting one mode never activates the other.

## Native OMP worker routing

OMP's `task` primitive accepts a worker selector but no per-call model, tier, or effort argument.
Woostack provisions three neutral project workers whose model fields point to OMP-owned role
aliases. OMP owns concrete models, provider credentials, thinking level, and retry/fallback
behavior; repository model leaves are ignored.

- Run `woostack-init` before review; gated `woostack-doctor` repair restores missing or drifted
  managed definitions while preserving other project agents.
- After review angle detection, OMP verifies the complete planned selector set in the active agent
  registry before launching any summary, angle, or validator worker.
- Review never generates or repairs agents and never launches a partial swarm.
- Batch dependency-independent bounded tasks in one dispatch.
- Pass the exact worktree and complete task contract.
- Workers return observations/changes; the controller owns synthesis and acceptance.
- If the spawn API cannot set cwd, pin it in the prompt and require the worker to verify it.

See OMP's published [model roles](https://omp.sh/docs/roles), [custom
subagents](https://omp.sh/docs/subagents), and the canonical
[host adapter](https://github.com/howarewoo/woostack/blob/main/skills/using-woostack/references/hosts/omp.md)
for the exact mapping and lifecycle.

## Isolated coder in the Hermes pairing

This path is explicit and optional. Hermes owns the active contract, decisions, independent review,
comments, acceptance, and escalation. The pinned OMP profile owns implementation and self-check for
one bounded task in one collision-safe worktree.

A unit pins:

- one stable engineer name and OMP profile/session;
- one distinct Hermes profile/session;
- one canonical worktree, branch, base, and current head;
- one complete bounded contract and permitted surface;
- isolated role credentials/config roots; and
- one expected evidence handback.

Build and standalone-plan runs require an exact project or explicit persistence request. A proved new
fix prompt is the narrow exception: after root-cause proof it binds or creates one compatible issue
through the configured official MCP. Neither profile requires a Linear principal or issue for normal
non-fix operation; a proved fix requires that configured capability and blocks before execution when
the required read, mutation, or independent read-back fails.

Before the first coder dispatch, create or resolve the canonical task worktree, then follow the
canonical [Hermes bound-unit setup](https://github.com/howarewoo/woostack/blob/main/skills/using-woostack/references/hosts/hermes.md#bound-unit-manifest-and-binding).
Dispatch begins only after that setup binds the unit successfully.

### Dispatch

Confirm the installed CLI's exact argv with `omp --help`. The conceptual command is:

```text
omp --profile <engineer> -p --cwd <worktree> <prompt>
```

Use an argument-safe PTY/process API. Never paste task or artifact prose into shell source. Require
the worker to verify profile, cwd, repository, branch, base/head, and allowed paths before writing.

The first dispatch implements and verifies only. It returns an uncommitted diff, exact commands and
observed results, or a decision request. It does not commit, push, open/update a PR, review itself,
accept work, mutate artifacts, or merge.

Hermes inspects the complete diff and performs specification then quality review. Only after a pass
may it redispatch the same OMP profile/worktree for one bounded `/woostack-commit` action. Hermes
then reads the canonical PR/head/diff itself and performs independent review.

## Linear artifacts

Build and standalone-plan runs select Linear only with an exact project or explicit persistence
request. A proved new fix prompt is the narrow exception: after root-cause proof it binds or creates
one compatible issue. Credentials stay in each profile's own MCP/OAuth secret environment and never
enter repository config, prompts, logs, staged launcher files, or generated output. Follow the
[Linear artifact contract](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/artifact-backends.md).

Artifact access cannot authorize worker dispatch, edits, commit, review, or acceptance. Before proof,
a fix makes no Linear call. `woostack-change` never contacts Linear.

## Recovery

Stop on profile, cwd, worktree, branch, ancestry, credential, process-exit, verification, review, or
submission drift. Preserve recoverable work and report the exact safe resume boundary. Never switch
profiles/worktrees silently or claim missing worker evidence.
