---
title: omp (Oh My Pi)
description: Host-owned role routing through omp's bundled workers.
---

omp exposes a `task` primitive with a worker selector, but no per-call model, tier, or effort
argument. woostack uses
[host-owned role routing](https://github.com/howarewoo/woostack/blob/main/skills/using-woostack/references/hosts/omp.md)
through omp's bundled workers. The canonical reference owns the fixed tier-to-role and
worker-selector mapping.

Selecting a bundled worker is full tier routing, not a degraded session-model fallback. omp
resolves the selected role to a concrete model and owns provider choice, thinking level,
credential rotation, and retry fallback.

omp ignores `.woostack/config.json` model settings. woostack does not generate project workers,
read or edit omp role configuration, or translate repository model preferences into host
fallbacks. Shared model settings remain available to other harnesses.

When the spawn API exposes a working-directory argument, woostack passes it. The dispatch prompt
always pins and verifies the worktree as a second guard. If omp recovery ends without a required
worker receipt, the calling workflow fails loudly rather than claiming thinner coverage.

See omp's published [model roles](https://omp.sh/docs/roles) and
[bundled subagents](https://omp.sh/docs/subagents).
