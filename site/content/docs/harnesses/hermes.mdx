title: Hermes Agent
description: Optional decision-maker profile, native delegation, and isolated OMP implementation pairing.
---

Hermes can use woostack in two ways. Its native `delegate_task` route is the default. An explicit
Hermes + OMP pairing makes Hermes the decision-maker and independent reviewer while a separate OMP
profile implements one bounded task. Build and post-proof fix paths require their exact canonical
Linear records and approval events; other artifact use remains optional.

See the canonical
[Hermes host adapter](https://github.com/howarewoo/woostack/blob/main/skills/using-woostack/references/hosts/hermes.md)
for host routing and degradation rules.

## Native delegation

Use `delegate_task` with a complete bounded goal and exact repository/worktree context. Prefer a
leaf worker unless the task genuinely needs another independent decomposition layer. Batch
dependency-independent tasks within the configured concurrency limit.

A child gets fresh context, so the dispatch must contain every contract, path, invariant, and
handback field it needs. Hermes owns scope, synthesis, gate enforcement, and acceptance.

## Optional Hermes + OMP engineer pair

The pairing follows the provider-neutral
[engineer-agent contract](/docs/concepts/engineer-agents):

- Hermes owns the contract, in-scope decisions, independent code/PR review, comments, acceptance,
  redispatch, and escalation.
- One isolated [OMP profile](/docs/harnesses/omp) owns implementation and self-check for one bounded
  task in one collision-safe worktree.
- Hermes never edits implementation source, runs implementation tests, commits, pushes, or opens the
  implementation PR.
- OMP never reviews or accepts its own work.
- Git/GitHub evidence owns source, ancestry, branches, PRs, review, and delivery truth.

### Required isolation

Pin one stable engineer name, distinct Hermes and OMP profiles/sessions, role-owned credential and
config roots, one canonical worktree/branch/base/head, one bounded task contract, and one expected
handback. Profiles isolate host state, not the filesystem or inherited Git/GitHub credentials;
worktrees and role-specific environments supply the actual boundary.

Do not dispatch on profile-name or config claims alone. Verify the active executables, profile,
repository, worktree, branch/ancestry, credential surfaces, and required capabilities.

### Safe setup and bound-unit manifest

Follow the canonical
[Hermes host binding contract](https://github.com/howarewoo/woostack/blob/main/skills/using-woostack/references/hosts/hermes.md#bound-unit-manifest-and-binding).
It owns the fixed setup order, exact manifest schema, file modes, static binder, and pre-dispatch
verification. This page does not redefine that installed-skill contract.

### Dispatch and review

Use Hermes' argument-safe PTY process interface with the exact OMP CLI argv documented on the
[OMP page](/docs/harnesses/omp). Never interpolate task/artifact text into shell source.

1. OMP implements and verifies the bounded task, returning an uncommitted diff and evidence.
2. Hermes reads the complete diff and performs specification then quality review.
3. Only after a pass may Hermes redispatch the same OMP profile/worktree for one bounded
   `/woostack-commit` action.
4. Hermes independently reads the submitted PR/head/diff and performs the PR review.
5. An in-contract correction returns to the same coder/worktree. Contract changes go to the user or
   owning decision-maker.

Use this parameterized decision-maker handoff:

```text
You are the decision-making engineer for ENGINEER_NAME.
Hermes profile: HERMES_PROFILE. Isolated coder: OMP_PROFILE.
Repository: REPOSITORY_PATH. Approved bounded contract: TASK_CONTRACT.
1. Re-read the approved contract, allowed paths, non-goals, and acceptance criteria.
2. Verify ENGINEER_NAME and the exact distinct Hermes and OMP profiles.
3. Verify the canonical repository, base, branch, and current head from Git/GitHub.
4. Create or resolve one collision-safe canonical task worktree.
5. Stage mode-0600 unit.json with the documented exact bound-unit schema.
6. Run bind-engineer-unit and verify adjacent mode-0400 unit-authority.json.
7. Dispatch OMP for implementation and verification only; do not grant commit, push, PR, review, acceptance, or merge authority.
8. Require the complete uncommitted diff plus exact commands and observed results.
9. Read the complete diff and perform task-specification review.
10. Perform an independent quality review on that same diff.
11. Read the canonical verification evidence and stop on missing or conflicting results.
12. Do not ask OMP to review its own work; Hermes owns the review and verdict.
13. After both reviews pass, freshly re-read authority and Git state, then redispatch the same OMP profile for exactly one bounded /woostack-commit action.
14. Independently read the submitted PR, head, base, and complete diff from GitHub.
15. Post your own GitHub review comments or verdict; advisory reviewers never replace Hermes acceptance authority.
16. Accept, redispatch an in-contract correction, hand off a contract decision, or report the exact blocker. Never merge.
```

No paired step merges.
## Linear artifacts

Build always resolves one exact Linear project or creates one from validated defaults before
ideation. After root-cause proof, a new Fix resolves or creates one project and its strict
direct-issue plan. Each profile uses its own official MCP/OAuth secret store and independently
proves the required project/issues, fingerprints, dependencies, responsible-user approval events,
and read-backs. Follow the
[Linear artifact contract](https://github.com/howarewoo/woostack/blob/main/skills/woostack-init/references/artifact-backends.md).

The two exact responsible-user approval events clear only their matching fix/build project-spec and
execution-plan revisions. Linear never supplies assignment, dispatch, commit, review, product
acceptance, or repository delivery truth. Before proof, a Fix makes no Linear call. Required
capability failure blocks fix/build at the retained boundary; artifact-optional workflows can
continue without their selected artifact operation. `woostack-change` never contacts Linear.

## Recovery

Stop at the last verified boundary on worktree, ancestry, credential, process-exit, verification,
review, submission, or read-back drift. Preserve recoverable work. Never silently switch profiles,
worktrees, or roles.
